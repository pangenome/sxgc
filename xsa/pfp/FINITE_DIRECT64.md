# Sample whole finite keys before writing postings

The [real 100 MB coarse-index result](../../gates/receipts/finite-emit64-100m/) spent 39.3 s planning local splits and 107.8 overlapping lane-s gathering filtered offsets. It decoded **14.46U** postings, and fit just 1.72 leaves per wave on average. Do not fix that by allocating an entire two-code cell or comparing rows in the publisher.

`finite_emit64 sampled RAW INVERSE NEW_POSTINGS WORKERS ARRAY_BYTES OTHER_FILE_BYTES DESIRED_DISTINCT_PER_RANGE TOTAL_SLOTS STOP DEADLINE > pipe` keeps the same view, aggregate eight-byte slot arena, local fallback, tie union, bounded packet rings and raw row ABI. The alternative **routes directly to usually-final lexical ranges**:

1. For `U` distinct offsets in lexical-head order, take one deterministic jittered sample from each of `min(U,64*requested_ranges)` equal ordinal strata. Walk the heads once in 64 fixed rank shards using their already certified owned extents, skipping over unsampled offsets. This is a head walk, **not an extra full decode**. Sort the sampled finite strings, not full byte suffixes. Use lexicographic quantiles as boundaries, dropping repeated boundaries and the minimum sample key. Each actual threshold is witnessed, exact equals always go to the same side, and the minimum sample lies below the first threshold.
2. Each two-code cell stores the interval of thresholds sharing those codes. Most cells have none. Within a contested cell use a cached projection of up to eight following bytes; if equal, compare the real bounded strings (including exhaustion/terminal semantics). Zero padding is NOT an equality test. Two descriptor walks: count every range **exactly**, then write its EF slices in parallel. Inter-range order is exact regardless of sampling bias. A range that still exceeds the arena goes through the existing bounded local planner; a giant exact tie bypasses the arena. The common prefix of adjacent pivot keys is safe to skip when projecting values **inside** the corresponding range.
3. Desire roughly five evenly sized ranges per full sort arena, so four concurrent sort lanes have room even with moderate skew. No assumed balance: count actual maximum descriptor and occurrence loads, 16U replay, active lane-seconds and all certified output fields.

**File cap drives sampling, not vice versa.** For `B` ranges, four disjoint producer stripes, and virtual universe `V≤32m+U−k`, a universal byte bound is `ceil(min_l [U*(l+1)+B*floor((V−1)/2^l)]/8) +16*B*workers`. This follows by using one EF width in every range; per-slice optimization cannot cost more. Binary-search the requested range count down to the largest allowed by `2N−OTHER` if necessary, then charge the actual file extents again. Given known 100 MB `U,k`, 192,001 slots, target 38,400 descriptors, up to 2,486 ranges, upper for file + private inverse + 4 MiB margin **199,532,024 / 200,001,006 B**. The smaller coarse index wrote fewer logical bytes: this design trades some file payload for less repeated traversal. Every emitted-byte stream must still be independently verified.

**Preventing subpage rewrite amplification.** Each EF column has two extents: page-aligned 4 KiB interiors, followed by its residual `<4 KiB` words in a common packed fragment region. Disjoint lanes write full pages into their own interiors; a short high bitmap may end with one partial write to its exclusively owned next page. Hold the final fragments in their existing lane buffers. After all lanes finish, concatenate the fragments once with a 256 KiB buffer, zero-filling only unused reserved high tails. No per-stream 4 KiB file padding, no overlapping writes. Decode the two extents sequentially. Logical populated EF bytes, bytes explicitly written, full file extent, process-attributed write bytes and device counters are different measurements.

`finite_emit64 sampled plan 100000000000 3181334488 1 100000000000 38400000 192000000 4` conservatively reserves arrays for up to 2,605 desired ranges independent of unknown vocabulary: **149,890,044,352 B** max incl raw producer. If `U=N,k_min=1` for the upper calculation, the file cap clips the count to 1,992 and gives **199,990,580,220 B** incl inverse/margin. A smaller measured U may allow *more* ranges. Only **9.42 MB** below the cap in that example: no implicit allowance for retained tape, key witness or additional output scratch. Not a 100 GB grant, benchmark or joint finish guarantee.

**[100 MB qualification passed](../../gates/receipts/finite-direct64-100m/)**: 93.489 s to independently verified EOF vs 276.754 s, one decode per distinct offset, 3.164 active order lanes and effectively unchanged attributed IO. 34.124 s remains in publication; not an index or scale admission.
