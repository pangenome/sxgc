# Reserve joint scratch by reusing one capped posting file

The [tiled 100 MB emitter](../../gates/receipts/finite-tiles64-100m/) proved byte order but consumed **195,533,144 / 200,001,006 B** incl inverse and margin. The remaining 4,467,862 B cannot hold even the finish bitmap. A faster local comparison (the [cache treatment](../../gates/receipts/finite-cache64-100m/)) did not address file lifetimes. Simply reporting that both a producer and a finish fit on their own is not a joint space bound.

`finite_emit64 epochs RAW INVERSE NEW_SLOT WORKERS ARRAY_GRANT NONPOSTING_RESERVATION DESCRIPTORS_PER_RANGE TOTAL_SLOTS STOP DEADLINE > pipe` keeps the ordinary tiled comparison sort. `NONPOSTING_RESERVATION` includes the entire retained inverse, controls and any headroom held out for another stage. This mode never unlinks any source or output. It trades **more distinct-offset walks for less simultaneous scratch**, not for fewer total posting bytes.

1. Draw the same deterministic finite-key splitters at the requested granularity. One exact census gives each range's distinct/row counts and the EF low/high extent in each rank stripe. Form the very same disjoint sort waves as the single-file emitter (up to four ranges, same total 8-byte slots). Before opening a file or writing END, greedily pack consecutive whole waves into ≤8 epochs, each ≤`2N − reservation`. Refuse a range larger than the sort arena, a wave too large for the file cap, or a ninth epoch. This **fit-only** mode does not silently switch to an unknown amount of local refinement mid-stream: larger inputs need an actual fit observation or another certified policy. The single-file fallback is retained. Check both route and emit array reservations and plan *all* jobs before opening.
2. Create one named private regular slot with `O_CREAT|O_EXCL|O_NOFOLLOW`. For each epoch walk all `U` distinct offsets (charge them even when a two-code range skips further classification); encode only this consecutive set of bands. Build the shared rank-page bitmap on the first encoding walk only. Place whole-page interiors then subpage fragments within each epoch. Encoder buffers die before the local sort arena and successor marks allocate. Fsync, open a checked read-only descriptor, read/hash the **actual complete extent** for the study, then consume the preplanned jobs through the bounded cat queues. Thread joins, row counts, and true preceding finite span carry across the seam; only one global END and one verified EOF. Do not infer throughput from a count of scans.
3. When all readers/lanes for the epoch have returned, check dev/inode/size/nlink against both descriptors and name, close the reader, then truncate the **same, still named, exclusively created inode** to zero and size it for the next epoch. This also clears holes/unused high-stream suffixes when sizes repeat or regrow. Never overlap two payloads or count an unlinked/open inode as freed. Charge the **peak slot extent throughout**, not just the small retained last image. Old outputs, existing hardlinks and symlinks are refused (no overwrite/reopen-for-update option). STOP or partial output cannot certify the stream. Last image and small per-epoch records remain. This is temporary routing, not durable publication of an index.

### Space/work prediction

For `v=32*(m+floor((U−k)/32))`, a four-range wave with at most `S` descriptors has at most `W = ceil(min_l [S(l+1)+4*floor((v−1)/2^l)]/8)+16*4*4` EF bytes. Count fewer bands/descriptors if appropriate. No four-wave padding tax on disk: the exact sum of all epoch extents is the original full layout's sum of slice bytes. Every nonfinal greedy epoch holds **more than `cap−W`** or the following wave would fit. So when `W<cap`, number of epochs ≤`ceil(total/(cap−W))`, provided all individual ranges fit. Census, repeated encoding visits, actual written bytes, readbacks, post-index decodes, and simultaneous live extent are distinct quantities.

* Matched 100 MB: `cap=floor(N/2)=50,000,251`, nonposting reservation **150,000,755 B**, of which 25,364,248 B inverse and 4 MiB margin. At least **120,442,203 B held out** for other live scratch, not measured consumption by a finish. Actual producer stage incl margin ≤**79,558,803 B** before running. Banked total 165,974,592 B, `W≤335,670 B`, every range ≤56,784<192,001 slots; both lower and upper predict **exactly four** epochs, 4U encoding visits + 1U census + sampling work, 1U post-index decodes, no local replay. The array upper rises from 247,981,272 to 251,389,144 B (still below 320 MiB); do not assume no cost.
* 100 GB conditional example only: actual `m=3,181,334,488`, `k≥1`, `U≤N`, 192M slots, 2,605 desired ranges at worst dimensions. With 50 GB slot and 150 GB other reservation, total logical posting upper **178,543,136,719 B**, largest fit wave ≤336,634,375 B, ≤4 epochs **if every range fits**. Inverse retained: stage live ≤75,454,870,208 B incl 4 MiB, **124,545,129,792 B** left for other live files. Producer array upper **149,898,703,072 B**. This supplies neither actual vocabulary/range skew nor a combined finish/oracle/relay memory or time grant. No 100 GB admission. Offline: `python3 -BE gates/overlap_finite_epoch64_study.py bounds`. Native `epochs plan N M K U TARGET SLOTS TEAM RESERVATION` reports conditional file/workspace limits only.

**[The real 100 MB arm passed](../../gates/receipts/finite-epoch64-100m/):** four image digests proved against the full control and every byte row correct, 70.306 s prepared→independently verified EOF. Actual geometry 79,454,952 B incl inverse and margin, leaving the full 120,442,203 B reservation unspent. This is not a completed finish or a raw-input time. A [post-close reconstruction of the historical v8 finish](../../docs/overlap_finish_credits.md) found a **123,611,895 B downstream floor**, larger than this reservation. It gives a conditional smaller credit/grid schedule, not a joint run.

### Fixed 100 MB component test

One new rolling arm vs frozen tiled **76.964 s** control, *not* the cache-sort miss. Same cold raw+inverse, 4 cores / 512 MiB / 320 MiB arrays, 192,001 slots, independent fifth core / 140 MiB whole-byte checker, zero swap and original row SHA. No control payload, adapter, ranker, front or finish rerun. Require identical ranges, waves, tiles, packets, groups, verified rows and every epoch's post-fsync image digest. Old global file = all interiors followed by all tails, in the same band/stripe sequence. A separate 192 MiB/one-core post-close proof streams the entire frozen control once, updating one digest per epoch from its two disjoint pieces, verifies the known full control SHA, and byte-compares the final retained slot. Earlier slot contents are authenticated by their full readback digests, **not** claimed to still exist. Candidate hash readbacks are charged *inside* its service time; final independent proof clock separate. Account for both additional raw copies, logical/allocated scratch, total explicit writes vs peak and attributed IO (`io.stat` may be null).

Predeclared space mechanism: exact four complete encoding walks, no changed tiles/decodes, counted stage upper ≤0.41× prior and reserve ≥1.20N. Component trade must also keep prepared→verified EOF ≤1.30×, CPU ≤1.25×, producer reads/writes each ≤1.05×. A miss remains evidence; do not relax caps. One 601–1,000 s lease in `gates/overlap_finite_epoch64_study.sh`. No change to product defaults and no automatic scale dispatch.
