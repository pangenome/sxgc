# Aligned suffix navigation without retaining the dictionary or key column

**Inputs:** the immutable raw text and its one-based, text-order `inverse.u64`. **Output in memory:** an occurrence view indexed by *parse* rank: raw start, predecessor byte (256 at zero), successor rank (`Psi`, zero at EOF), adjacent byte LCP, range-minimum LCE, and consecutive head ranges with their canonical `dictionary.lex64` byte addresses. It does not materialize an SA or LCP of *all byte positions*. It does not read an ID column, dictionary tape or list spool. This complements the [dense lexical-column reference](RANK_VIEW64.md); keeping raw is a deliberate trade, not a corpus-free build.

```
g++ -std=c++20 -O3 -Wall -Wextra -Werror -fopenmp xsa/pfp/tools/raw_rank_view64.cpp -lcrypto -o view64
view64 plan N M WORKERS
view64 RAW INVERSE.u64 WORKERS ARRAY_GRANT_BYTES STOP_PATH DEADLINE_UNIX
```

### What is parallel and why it is safe

1. Divide raw **bitmap words** among workers and mark all FNV trigger starts plus the mandatory start at zero. Eight-byte trigger tests may read across a worker cut. Exclusive prefix of lane counts gives each worker its text-ordinal interval. Each reads its own corresponding contiguous rank slice and one lookahead. At rank `inverse[j]` store the raw position and `inverse[j+1]` or 0. Before either write, atomically claim one destination bit: a corrupt duplicate rank must be rejected, not become a data race. Byte-rounded packed slots do not share storage bytes. Keep the first rank of each text stripe. Then release the entire trigger bitmap.
2. For rank `r`, let `p=position[r]`, `q=position[Psi[r]]` or `N` at the end. The raw word is `text[p..q+8]` if nonterminal, `text[p..N]` otherwise. Every pair of adjacent ranks must have strictly increasing `((raw,terminal),Psi)`. This checks lexical suffix recurrence against actual text and fixes group boundaries; head ranges already are lists in successor order. Reuse the bit-claims allocation for head starts. **64 fixed rank shards** each compare against the preceding rank across their seam. Prefix-sum their distinct record widths `8+raw_len`, with a carry for the last head, to reconstruct canonical 64-bit dictionary addresses in rank order. No `O(k)` directory required.
3. **Sparse byte Kasai.** Traverse `Psi` in text order within each stripe. For start `p`, let preceding rank's start be `q`, exact aligned LCP `h` and the owned stride at `p` be `s`. If `h >= s+8`, the eight bytes at `p+s` equal those at `q+s`: `p+s` is an ordinary trigger, so `q+s` is a trigger too. After stripping the first `s` bytes, `q+s` is lexically below `p+s` and witnesses **at least `h-s`** common bytes for the predecessor of `p+s` in aligned order. Otherwise seed zero. Extend from this proved lower bound, check the first mismatch or suffix exhaustion, and store the result by rank. Start each parallel stripe at zero—no cross-worker carry/race. Each step can discard at most `s+8` before the next one. Across w stripes the number of matching bytes newly extended is bounded by `N+8m+wN` including boundary overhangs. Repeated long aligned suffixes do not force a fresh scan of every shared byte. A pair of word lengths alone does **not** justify carrying a byte LCP if the shifted comparison doesn't reach a full trigger.
4. Reduce adjacent LCPs into 64-entry block minima in parallel, then finish the small tree. `lce(a,b)` uses at most two partial blocks and a range query; END gives zero, a rank with itself gives `N-position`. The slow variable-length comparisons, random permutation writes, stripe imbalance, memory bandwidth and final proof are measured separately. Four threads do not imply fourfold speedup.

### Liveness and the 100 GB path

All public coordinates, counts, range and key arithmetic are u64 (checked extent math in u128). Internal position/LCP fields use `p=bytes_needed(N)` and successor ranks `r=bytes_needed(m)` (including virtual zero). These are general 1–8-byte encodings, not a 32-bit limit. With `b=ceil(m/64)`, the admitted resident upper including the raw mapping is

```
N + (p+r)m + 8b                         # raw, sorted starts/Psi and claim→head masks
  + max(8ceil(N/64), p*m + 16b)         # trigger bits OR aligned LCP + minimum tree
  + 4 MiB + 2 MiB per worker
```

The rank file is **streamed** with bounded `pread` buffers, not another resident array. Kernel cache, runtime and independent auditor live sets are separate. At actual 10 GB dimensions: **14,586,197,448 B (13.58 GiB)** at four workers. At measured 100 GB `m=3,181,334,488`: **145,744,266,192 B (135.73 GiB)**, independent of unknown vocabulary or max LCP. Both have 5-byte raw coordinates and 4-byte ranks here; wider universes select wider slots. This is a view-stage bound, not an emitting arena or grant. Only ~4.27 GiB of an illustrative 140 GiB remains for concurrent arrays at 100 GB.

**Proposed file lifetime, not deletion authority:** if finite-tail ordering can use the same raw spans, independently authenticate the front's generated tape/keys against raw, record their digests, close and retire *only the new private tape* before opening the inverse output. Keep native keys through independent rank/navigation certification. Front and rank/view file peaks then use `max(T+8m,16m)` rather than `T+16m` for `T=U+16k-8`. At actual 100 GB `m`, the upper plus 4 MiB margin is **176,356,222,008 B** for these phases. No compact-map reconstruction or full-rank write alongside a worst-case tape needed. Never retire a preserved input, or count a still-open unlinked inode as free. The present study keeps all original evidence untouched; no end-to-end v10, 100 GB resource admission or downstream scratch guarantee follows from this schedule.

**Measured at 10 GB:** [the independent full aligned-start qualification](../../gates/receipts/raw-view64-10g/) passed for both arms. 75.386 s ready vs 261.583 s (four vs one), 105.066 / 373.042 s incl. field attestation. Not a full suffix-row stream.

### Fixed real-column qualification

`gates/overlap_raw_view64_study.sh DEADLINE` is limited to the already authenticated 10 GB raw input and the certified native inverse. Two same-binary arms **4 then 1** under the same four-core affinity, four-CPU quota, 20 GiB shared / 14 GiB arrays, zero swap. Hash and privately cold the inputs; cold-check the same immutable inodes between arms. Compare prepared **raw+inverse → ready in-memory view**, and separately metered service including complete ordered-field attestations. This is not raw text → finished product. No repeat of the rank sorter or either lexical front. Predeclared parallel goal **≤0.80× ready wall and ≤0.90× full service wall**, reads ≤1.05× and each worker writes ≤2 MiB; correctness/fit reported even on a miss.

Every aligned slot contributes to canonical SHA-256 shard roots: LE `(raw_position:u64, byte_LCP:u64, predecessor:u16)` and `(native_key:u64, successor:u64)` in rank order. Shards/roots do not depend on thread count. Across all nonempty shards additional END, self, crossing and arbitrary rank-pair LCE queries have a separate root. This tests **all adjacent values**, not every quadratic RMQ pair. Only after both builds close, copy the independently certified native text-order keys for the single-CPU / 14,000 MiB oracle. The oracle recomputes raw starts, permutation and every adjacent byte LCP by **direct raw comparison from zero**, not the carry algorithm. Drop raw before the independent key/successor pass. Compare all fields, sums and roots; cap direct comparison work at 384N matching bytes and enforce IO/time stops. There is no 318M-row proof file. For this intermediate, sequential separate certification is intentional; full byte streams still need the concurrent raw checker. Python fixtures independently reconstruct the exact wire from a brute raw suffix sort, including a dense unary adversary for which the oracle correctly refuses excess work.
