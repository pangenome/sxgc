# Cache raw spans only when the projected finite prefix collides

The [tiled 100 MB control](../../gates/receipts/finite-tiles64-100m/) spent **57.469 of 76.964 s** ordering. Gathering was 28.746 lane-s; sorting *after* gather took 151.568 lane-s. The old comparator compares cached prefix bits first but reopens both aligned word spans on every projection tie. Recovering a span can require the head position, successor and its position from three packed columns. The old measurement did **not** count such comparisons or cache misses. `finite_emit64 cached` tests whether avoiding repeated decoding of those random-access fields removes most of sort time. It keeps the sampled router, same posting layout and single descriptor arena, packet sizes, tiled publisher and checker. No extra sort workers.

**Invariant.** The low `p` bits of a slot always identify its original distinct offset. Its initial high `64−p` bits hold a monotone zero-padded projection after a proved common prefix. Numerically order just those high bits in place; this partitions the array into lexical intervals but is **not** a final sort of ties. In an equal-projection run at least `floor((64−p)/8)` more whole bytes match up to the shorter key's end. Don't skip the rest of a partially projected byte; don't equate padding to terminal. Treat only the common *real* prefix as known.

* For at most `min(512,2^(64−p))` entries decode each bounded raw span once. Cache its next 8 real bytes (zero-padded), address/length of the rest, and `(full_length << 1) | EOF`. In this run every slot's high bits were identical; temporarily put a local cache ordinal there. Sort the original slots by cached next prefix, bounded remaining bytes and full length/tag. Restore the single high projection after sorting. A pair needs no ordinal. Descriptor identities travel with their slots, not in another permutation array.
* For a larger run, refill the slot's high projection from its raw span at the newly proved depth and repartition. At most **two** refills per descriptor; for a uniform projected run no numeric partition sort is needed. Equal projections **plus** identical length/tag and all bytes covered prove an exact class without extra compares. After the refill cap (or with no whole byte available) finish that run with exact bounded comparisons. This protects correctness with a 64-bit payload and zero spare prefix bits, though a large deep-prefix run can still be slow. A projection/ordinal is never an independent suffix-order witness.
* Equal finite keys stay together and reload the same high bits; distinct adjacent groups needn't have comparable high bits once a run is sorted. Tile planning uses them only as an inequality filter followed by exact comparison. No other code interprets them as global rank. The class's internal descriptor order is immaterial: expansion takes the ordered **union** of its continuation ranks, producing deterministic positions and exact byte LCPs.

Working set is 512×32 = 16,384 B of span metadata plus 8 KiB call/control allowance per simultaneous ordering lane: **98,304 B / four lanes**, no auxiliary descriptor slots, no extra posting or file pass. The cache is per *active lane*, not per range or class. At hypothetical worst 100 GB dimensions `cached plan 100000000000 3181334488 1 100000000000 38400000 192000000 4` gives producer array upper **149,897,143,104 B**; the file bound and joint-finish limitations don't change. This model doesn't predict how often larger ranges, fewer projected bits or actual ties at 100 GB would reach the fallback. Unit cases include 11–64 payload bits, shared prefixes >64 KiB, exhausted/terminal and embedded zero bytes, identical strings, forced refills and fallback. The unit counts calls to the supplied span accessor independently of the sorter's counters.

**[100 MB observation](../../gates/receipts/finite-cache64-100m/):** all rows exact. Order wall 36.239 vs 57.469 s; sort-only lane-s 68.246 vs 151.568. 2.0273 span loads/offset and 64.511 s verified wall missed the combined target; no promotion. The 2.15M fallback descriptors accounted for 55.54M decodes. Do not infer a wide-rung win.

## One fixed, matched 100 MB test

New candidate only versus archived tiled control (score `b61006c8d8af7eb2b90ae9fe38005e3ddc2185aa16d1414af7948dd301ebe825`). 601–1,000 s lease, cold authenticated private raw+inverse, four cores / 512 MiB shared / 320 MiB array / 192,001 slots; concurrent one-core/140 MiB raw checker. No swap. Same independently verified EOF and narrow SHA, byte-identical deterministic posting payload in a separate post-close proof. Exact same ranges, decode count, 63,177 tiles, packets, tie/group mass and scratch bound. A changed within-tie descriptor order is fine; a split tie or changed byte row is not.

Mechanism: post-gather **sort only** raw span loads = cached descriptors + refill descriptors + 2×exact fallback comparisons. This excludes the initial gather, row expansion, cache hits and bytes read inside a raw span; not a count of IO or hardware cache misses. Require **≤1.50 loads per distinct offset**, **≤0.60×** sort-only lane-s and **≤0.65×** order wall. End-to-end goal additionally **≤0.80×** prepared→verified wall (61.571 s) and each attributed producer IO direction **≤1.05×**. Report counters, clocks and any miss. No rerun of a successful control, no promotion to a product or larger scale based on this observation.
