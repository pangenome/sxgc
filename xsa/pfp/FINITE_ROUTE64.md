# Routing finite word offsets without spooling suffix rows

Starting point: [raw + inverse → aligned occurrence view](RAW_RANK_VIEW64.md), independently proved at 10 GB. A view by itself needs an entire dictionary walk for each disjoint output band unless there is an index *into the distinct offsets*. One ordinary word with frequency a million contributes **one posting per owned offset, not a million**. This index does store `U` compressed coordinates. It is neither a byte SA nor the final order of the descriptors, and must be counted as a real scratch file. No position/LCP/predecessor rows are written.

**Address space.** Give every one-based parse rank a base page of 32 virtual slots. At the head of a lexical word owning `s` bytes, insert `floor((s−1)/32)` extra pages immediately after its base. Emit `base*32 + offset`, `0≤offset<s`. Nonheads reserve only a virtual base page; emit nothing. Tokens increase within each rank stripe. A bit marks each extra page. For page `j`, owner rank is `j+1−popcount(extras[0..=j])`; offset is `32*(j−preceding_base)+slot`. A pair of u64 anchors every 512 pages bounds rank and preceding-base lookup to eight words even inside a very long phrase. No dense `(word,offset)` file, no giant inverse descriptor directory. The virtual universe has `V=32*(m+sum(extra))≤32*m+U−k` coordinates. Rank/offset arithmetic is u64 with checked wide extents; a coordinate universe not representable in u64 is refused. This is not a u32 word-ID format.

**Two descriptor walks instead of one walk per band.** Four disjoint rank stripes can count distinct offsets and occurrence-weighted rows in 65,792 cells (first byte, second byte+1 or zero for exhausted EOF). Greedily coalesce adjacent whole cells up to a row target, leaving oversized cells intact. Every finite equality class stays in one band; this is routing, **not** a certification that all bands fit an ordering arena. The second walk writes monotone postings in parallel to one new, fsynced file: each `(band,stripe)` has its own disjoint slices, no shared writer lock or row comparison. Only extra-page masks potentially share a seam word and use atomic marks. No disk cache eviction claim in the library.

For `c` distinct local coordinates in a stripe universe `v`, an Elias–Fano payload uses `c*l` low bits and `c+floor((v−1)/2^l)` high bits (bit `(x>>l)+i` set for coordinate `x` at ordinal `i`). Choose minimizing `l` in 0…63, round each column to 64-bit words. Empty streams cost zero payload. Read each column sequentially, reconstruct every coordinate exactly, then locate its head and offset. Working metadata stays with the resident view; the scratch payload is **not** a standalone reusable file format. Repeated attempts never overwrite an earlier inode. The pre-open guard counts the private inverse and all caller-declared other live files plus the entire logical payload, not just written nonzero pages.

**A 100 GB *upper* without guessing its vocabulary.** For any fixed `l`, the expression above increases with `c` and `v`. Distinct counts are bounded by the measured occurrence counts in each band. Summing the high terms across disjoint stripes costs at most the one whole-universe high term. Per-stripe optimization can only lower this bound; charge an additional 16 B per stripe and band for word rounding. `python3 -BE gates/overlap_finite_route64_plan.py` uses the pinned scan histograms (plus exact 10 GB descriptor census when available); does NOT open a corpus. Target `max(128,ceil(N/1024))`, four workers:

| Bound (bytes) | 10 GB, measured `k,U,c` | 100 GB, `k≥1,U≤N,c≤mass` |
|---|---:|---:|
| Bands | 578 | 577 |
| Page/anchor arrays upper | 93,144,936 | 985,364,776 |
| Posting file upper | 12,923,499,594 | 140,993,157,361 |
| File + private inverse + 4 MiB margin | 15,473,009,802 | **166,448,027,569** |

Neither the native tape nor an expanded descriptor file is in that ledger. Even retaining separate `8m` private oracle keys gives ≤191,898,703,473 B in the 100 GB **routing phase**; retaining the tape on top is not justified. Preserved inputs are not deletion candidates. No bound here for the whole finish; check each overlapping lifetime. Arrays for the view, census, buffers and index plus cache/grants are separately charged. More/lower-capacity bands can change the bound: use the actual plan. Standalone fixtures compare every routed `(head,offset)` to a direct raw suffix sort and independently check the exact file extent.

**Open problem after routing:** 204 of the 577 100 GB bands are single above-target cells containing 74,142,226,608 *occurrences*, not necessarily that many distinct offsets. Largest occurrence cell 2,310,198,593. Don't reserve a whole unlimited cell or split a finite tie arbitrarily. Local subdivision or temporary runs need their own scratch/time bounds and evidence. An index of finite offsets is not a stream of certified suffix rows.
