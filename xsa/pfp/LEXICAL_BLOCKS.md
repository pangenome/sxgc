# Avoid retaining one position, one count and one full copy of every dictionary word?

**Result: exact on fixtures, not a scalable producer yet.** `src/overlap_lexblocks.rs` and `src/overlap_nav.rs` are used by integration tests only. They are not in the timed 1/10 GB product, not a replacement 100 GB indexer and not an allocation or throughput grant. Run `cargo test --locked --offline --manifest-path xsa/pfp/Cargo.toml --test overlap_lexblocks --test overlap_nav`. All test data is synthetic; the codec builder refuses over 10,000,000 bytes of input records. The optional independently verified [10 GB vocabulary study](../../gates/overlap_vocab_census.md) can measure **codec wire sizes** during its *post-clock reference pass*, without writing a compressed dictionary or changing the candidate timer.

### Random byte access without unfolding a restart block

Input is the complete deduplicated lexical sequence `(raw,EOF)`. Every 4, 8 or 16 words start a new block. At a restart store `ULEB(2*len+EOF), raw`. Otherwise take `p = LCP(previous.raw,raw)`, and store `ULEB(p), ULEB(2*(len-p)+EOF), raw[p:]`. Use a u64 payload offset per block and one final offset. Zero literal length does not erase EOF. This is lossless even when the same raw bytes appear once with each tag. Comparison on finite tails excludes SEP, and virtual END sorts below all 256 possible raw bytes. Non-EOF owns `len−8`, EOF owns `len` offsets; EOF's one explicit END is a symbol but not a raw byte in an LCP. There is a separate global END row.

`word(id)` parses ≤16 bounded header pairs. A header truncates the predecessor's views to length `p` and appends a literal view. Skip each literal body by its length, **without decoding/skimming all its bytes**. Induction gives ≤16 live slices referring into this one immutable block. A symbol query finds its slice by a bounded binary search and does one indexed byte load; no word copy. Headers can be at different cache lines and long-prefix comparisons still cost byte lookups. A view is a few hundred **stack bytes**: keep at most a few ephemeral views per comparator/worker; do not casually attach one to each heap cursor. No sequence of random lookups is claimed to be sequential storage IO. The intended dictionary is resident. A [fixture-only direct-literal alternative](LEX_DIRECT.md) trades bounded per-block offset tables for shorter scattered-byte lookups; it is not a large dictionary loader.

### Recover text-order byte PLCP without a dense inverse or token PLCP at that phase

1. Sort/certify the parse **before loading the resident dictionary**. Build flat `Psi` + bounded samples (B=8) and save `rank(text occurrence 0)`. Check the head/successor recurrence. In rank order, head IDs partition the parse SA into `[loc(h),loc(h+1))`. Because the k IDs are dense and nonempty, `loc(h)−h` is monotone in `[0,m−k]`. `Heads::from_sorted` streams the k+1 boundaries directly into the [block-64 succinct column](OVERLAP_NAV.md), refusing missing heads, unordered IDs, wrong lengths. The old `8k` counts **and** `4(k+1)` loc array are unnecessary for this query adapter. `slots(id).len()` recovers counts. Drop construction SA/inverse; retain only IDs of the parse plus navigation.
2. `Aligned::from_parse` streams succinct starts by adding each ID's **owned** length. Require correct N and unique final EOF ID. Iterate text positions `j=0..m` with rank `r`; check its head-list slot. Advance ranks by `r=Psi[r]`, ending at zero. For `r>1`, `q=position(r−1)` is the lex predecessor occurrence (≤B−1 hops). Apply token-level Kasai carry `z`: the previous match minus its first **token** bounds the next match, except at first rank where carry is zero. Extend with equal token IDs. Compare the first differing dictionary words only. The raw PLCP is `start(j+z)−start(j) + raw_LCP(word[j+z],word[q+z])`. Equal tokens must also give equal byte strides on q. Unique EOF prohibits a match running beyond the last word. The overlap at the boundary is already in the first differing word, not an extra `8*z` bytes. Feed P straight into `P[j]+start[j]+7*j`, checking monotonicity and suffix boundaries. No dense byte PLCP, token PLCP, text start, ISA **or SA** is borrowed by this adapter. O(m) token extension work is not a bound on the cost of comparing differing dictionary words.
3. Also walk Psi in text order to scatter a predecessor byte per list slot (last owned byte of the previous word, not its lookahead tail). Override the dummy slot at text start by 256. Now drop the IDs. Build the rank block minimum tree on the succinct leaves. Lookup from a list slot recovers occurrence j and start(j); stream row at start+offset. Equal finite keys still require their successor-rank merge and within-tie aligned RMQ. The fixture combines this with brute finite-key grouping, then independently compares **every** `(position, LCP, predecessor)` to raw suffix sorting. Its materialized small groups and brute vectors are not part of a proposed scale algorithm.

### Account by phase, not by subtracting one array from a prior RSS

With actual 10 GB counts `m=318,164,488, k=234,472,723`, the new head column upper capacity is **205,163,672 B** vs 2,813,672,680 B of dense counts/loc. At **10× sensitivity only**, 2,051,636,328 B vs 28,136,726,764 B. Replacing just that pair in the previous optimistic dictionary-offset + navigation model still costs **155,820,539,849 B** before order and consumers, **5,496,684,489 B above** 140 GiB. The new codec aims to replace both tape `T` and the dictionary offset column; whether it saves enough is a measurement, not a theorem about this corpus.

`gates/overlap_vocab_plan.py::lexical_block_model` reports each exact lexical wire ledger (literal, payload, directory, peak block), and separate model terms for: 4k/6k wide parse sort without dictionary; constructing Psi + samples and heads with borrowed IDs/SA and temporary inverse; alignment with compressed dictionary + IDs + succinct columns, no SA/inverse/dense PLCP; and emit with rank-block tree instead of IDs. The small two-pass fixture retains its input. A future actual bulk loader would need a separately metered bounded pass for exact allocation (or accounted chunks), then a sequential encoding pass from the private lexical tape, with previous/current word buffers. Charge that tape, IDs, output scratch, order arena/cursors, views, remap, stacks, cgroup and both consumers at their real overlapping phases. There is no large loader, integrated MSD iterator, random-access speed evidence, width verdict at 100 GB, or v10 producer here. The 140 GiB reference is the **10 GB** array grant; 10× counts or payload densities are **not a 100 GB observation or grant**.
