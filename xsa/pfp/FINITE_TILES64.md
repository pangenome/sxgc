# Publish sorted intervals without making a full band wait on a three-packet ring

The [sampled 100 MB arm](../../gates/receipts/finite-direct64-100m/) spent 34.124 s publishing. While earlier intervals were being expanded the workers on later intervals filled their 3×2,048-row ring and stalled. The publisher slept for 32.952 s; the four producers reported 84.559 lane-s elapsed, of which 46.295 lane-s were blocked: (84.559−46.295)/34.124 = **1.12 unblocked expansion lanes**, not four. This is elapsed work, not sampled CPU attribution. The new `finite_emit64 tiled` experiment changes the size of the ordered units *after* routing and sorting, not the common pipe, oracle, sort, total descriptor slots or rows.

**Tile.** In each resident sorted wave, cut every 1,536 descriptors and extend right to the end of the exact finite key. Quantization/projection only rejects equality, raw/terminal comparisons decide ties. A refined exact-class bypass remains one tile even above the entire sort arena. Save each tile's preceding finite span, including the prior wave's terminal span; when expanding its first key, take the true finite LCP with that span. Within ties retain aligned-LCE/continuation union. Every tile is a contiguous interval of the final suffix order; no sequence, suffix, BWT or container changes. Compute ends in `O(number of tiles + additional descriptors in crossed ties)`, no per-descriptor mass scan. At most `ceil(resident_descriptors/1536)+live_jobs` tile records per wave. Four workers each have *one* marks set and 3×2,048 row ring, not one ring or one buffer per tile. Reserving that many tile records plus queue-control delta at 100 GB adds **7,000,448 B** to the worst-dimension four-lane emit plan (now 149,897,044,800 B, not a grant). No new files.

Assignment is static tile ordinal modulo actual lanes. Each lane receives increasing ordinals and holds no cross-lane resource, so a later full ring can't prevent the current head tile from continuing. Publish exactly one tile's packets at a time, each with ordinal/count/final flag; the last packet can be full. Every slice checks row bounds and each original range's aggregate must match its independent census before crossing its end. A giant, very hot class can still serialize its own expansion. No packet copying into a second reorder buffer, no row file and no external merge. Interruptible producer and consumer waits and nonblocking writes retain STOP checks. A pipe-only precondition still applies. Don't assume this reduces sort wall; it changes no compare/gather work.
