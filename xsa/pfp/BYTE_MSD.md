# In-place byte MSD for a finite-key band (fixture, not a promoted producer)

**Motivation.** The [qualified 100 MB shortest-tail component](../../gates/receipts/bounded-shortest-100m/) no longer pays for the dry order, but its one remaining local bit-radix pass across 16 ordered ranges needed 11,770,915,334 key-digit reads at 95,434,516 descriptors. At 105.232 s prepared vs 36.077 s resident it is within 3×, not 2×. The 11.77B is an operation count, not a clock. Change *only local order*, preserve whole-key planning, successor ordering, END and seam LCP. The bit kernel remains available and no measured producer or dispatch defaults to the byte kernel.

**Invariant and costs.** Histogram all 256 possible next bytes (0 is finite-key end, actual symbols >0). In a nonuniform interval place each descriptor into its actual bucket, advancing only that bucket's cursor; when a displacement is necessary read the displaced value on the next iteration. Exactly one histogram read per item; on a varying byte exactly one further key-digit read per item. No second descriptor vector. Uniform zero terminates, uniform nonzero advances one byte. Within sorted buckets recurse only on non-largest children; iterate the largest. In either direction the next depth is valid because 0 never recurses. Buckets of ≤32 items instead use binary insertion by the *remaining finite slice*, in-place, counting comparisons and shifted 8-byte slots. These slice comparisons may inspect many bytes and are **not** included in `digit_reads`. Worst case O(U(L+1)) radix probes plus leaf comparisons costing up to O(UL log 32); moves in a leaf O(32U). A long uniform prefix can still be costly. Group order within a tie is immaterial; the ordered group's callback still merges continuation ranks.

Each recursive large child has at most half its parent's items. For A available slots, at most `max(0,1+floor(log2(floor(A/33))))` large frames (zero if A<33), each two 256-usize arrays + eight scalar words reserved. On 64-bit add `4160*frames` to the conservative existing histogram/plan/binary-stack bound, then `8*A` for descriptors. Select the largest A fitting the same total arena by checked integer bisection. No largest-child recursion, per-range payload file, widened descriptor, new row/packet pool or enlarged pass cap. Counts are logical explicit payload: actual stack prologues, allocator and library/cgroup overhead are separate. Fixtures check each callback against brute full finite keys, proper-prefix cases, counts, explicit frames, seam LCPs, and raw row43 streams in `--fixture-byte-msd`.

**Measured decision: do not promote byte MSD.** [Crossover bank](../../gates/receipts/byte-order-fixture/README.md): every finite order verified, but worst bytes/bits wall was 1.005× book, 0.810× wide, 0.779× families. Fewer radix probes did not pay for extra classification and leaf work on the book. The required ≤0.65 book ratio failed; no 100 MB byte-sort timing or product dispatch. `python3 -BE gates/overlap_byte_fixture.py archived gates/receipts/byte-order-fixture` replays the small receipt, grants and score without reading any book or Pile data.

**Fixed small crossover and prior criterion.** `bash gates/overlap_byte_fixture.sh DEADLINE_UNIX` is a standalone in-RAM finite-key study, not Pile construction. Lease, clean published source, archived 100 MB observation; isolated 192 MiB / one CPU, no swap. 64 equidistant disjoint 3,072-byte windows of public-domain book `~/text/pg64317.txt` (306,317 B, SHA-256 `43b101cc636c0214414fb994b71b2180074f3ec0b11d5699e7ce81450688dbd3`); fully internal consecutive FNV triggers only, never join across windows. Exact word dedup and local counts. Other shapes: ≤1 MiB fixed-seed wide-alphabet windows, and 12,288 generated words in 128 long-common-suffix families. Each gets one marked synthetic final word. These represent finite-key shapes, not complete text parses. No original Pile file, packed column, suffix row or product. Native reads only a 196,608-byte in-memory input fixture; public book authentication/selection and deck generation are outside order clocks. No cold-data or device-locality assertion.

For each dictionary both orders get the **same** payload budget, the bit slots proportional to U as in the banked 100 MB arena after fixed charges. The byte implementation pays for its stack in that budget and may need more full scans. 32 total census/distribution passes maximum. Predeclared bits→bytes, bytes→bits; separate wall and native process CPU for complete order plus **the same** independent finite-group checker. Check every descriptor/equality against resident finite slices, strict order across groups, exact head LCP, occurrence mass and bitset permutation including every range seam. This is not a SHA-only performance promotion or a raw-row oracle. Small working sets don't reproduce 100 MB producer cache misses, list merges or downstream backpressure.

Prediction to consider another *separate* fixed-rung study: worse of the two bytes/bits wall ratios **≤0.65 on the book**, **≤0.80 on at least one generated shape**, and **≤1.10 on all three**; full validation and grants must pass. At actual 100 MB clocks even an across-the-board 0.69× prepared time would miss 2× resident. A fixture pass is only a reason to investigate; a refusal/miss is recorded without changing caps or rescheduling the same arms. No product or larger input authorized by this criterion.
