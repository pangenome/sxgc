# Compact finite-tail order: producer handoff, not a production gate

Compile `overlap_compact_order` alongside `overlap_range_order`. Pass the existing validated-format `Dictionary` to `order(d, Limits { workspace_bytes, rows_per_range, passes }, |tails, head| ...)`. Each borrowed `PackedTail { word: u32, offset: u32 }` selects a list; convert by `d.key(tail.into())` for its finite key. The kernel checks `k` and **each full encoded word span** against `u32::MAX` before narrowing anything; starts, aggregate dictionary positions, and row masses are not narrowed. It checks SEP/END, positive frequencies, valid owned extents, and arithmetic, not parse validity. Return is `Result<Counts, Refusal>`. All admission, including workspace reservation, precedes the first callback. `passes` counts census **and** distribution scans, unlike the reference cap.

**Order invariant.** The planner covers the ordered domain with disjoint bands. Within a witnessed prefix, histogram the next byte (virtual end = 0, less than every actual key byte); adjacent *whole* bins may coalesce under both limits. In an overfull bin the census has a witness, the longest prefix shared by every member, and the longest finite length. Equal shared and longest lengths prove an unsplittable exact class. Otherwise restart at the shared depth: all keys in the child match that prefix, and no key outside the child can match it. Every restart consumes a pass. The plan is an iterative array, with `completed census scans + current bands <= passes`; even an adversarial prefix ladder cannot authorize unbounded retries. At the cap the answer can be `PassCap` rather than a more specific diagnosis. Empty suffix offsets and global END are not emitted. A leaf's in-place MSD partitions only between distinct digit values; a uniform nonterminal byte advances depth, a uniform virtual end terminates. The ordered concatenation has no split ties. Group LCP is computed against the previous *global* group's representative, including at a band seam.

**Payload, not RSS.** For `k` words, `D` encoded bytes, `U` owned offsets, `P` allowed passes and `A` peak admitted descriptors, charge resident input `D + 8(k+1) + 8k`, then kernel `fixed_bytes(P) + 8A`. On this 64-bit build fixed = `10240 + 1536 + 40P` (one 256-bin histogram on stack plus an explicit 64-triple radix work stack and a preallocated plan); `A <= floor((workspace_bytes - fixed)/8)`. Allow additional vector headers, allocator slack, normal stack (the smaller side is processed first; at most `floor(log2 A)` larger siblings are pending), and process safety margin. No per-row key strings, device spool or second descriptor buffer. The resident dictionary is a prerequisite, not free page-cache capacity. Consumer is additional: for a materialized class of `r` rows with output records of `s` bytes, charge `r*s`, `r <= peak.rows <= rows_per_range`; for a streaming merge charge up to `peak.descriptors` cursors and heap entries times their actual strides, plus occurrence/continuation indexes, RMQ and bounded output queues. Do not expand rows without that separate grant. Callback must order ties by successor rank, supply within-tie LCP and emit global END separately, as in the reference interface.

**Operations.** One validation scan of input, then exactly `U*(census_passes+distributions)` logical tail classifications, with `k` word visits per scan. `distributions >= max(ceil(U/slots), ceil(total.rows/rows_per_range))`. Prefix filtering/census LCP can cost O(L) bytes per visit for maximum finite length `L`; no assumption that shared prefix comparisons are cache hits. Planning clears 256 bins per census; plan shifts cost O(P²) records overall (every inserted band eventually costs a pass). MSD's actual digit reads are counted: per descriptor per byte depth at most eight varying-bit partitions (two reads apiece) plus a uniform-byte check. Hence at most `17U(L+1)` even on tied/long keys, rather than an L-length comparator per sort comparison. Adjacent equality and incoming LCP checks separately cost O(UL) bytes. Neither digit reads nor descriptor visits are physical IO or CPU time.

**Checked fixture.** Reproduce single-threaded without the rest of the producer:

```
rustc --edition=2021 -Dwarnings --test xsa/pfp/tests/overlap_compact_order.rs -o /tmp/compact-order-test
/tmp/compact-order-test --test-threads=1 --nocapture
COMPACT_SAMPLE=$HOME/text/pg64317.txt /tmp/compact-order-test --ignored --nocapture
```

The sample reads 256 equidistant 64-byte windows (16,384 bytes total) of the 306,317-byte Gutenberg text SHA256 `43b101cc636c0214414fb994b71b2180074f3ec0b11d5699e7ce81450688dbd3`. Each is treated as one remapped word with synthetic frequency; **not** a PFP parse. Every `(head, sorted class IDs)` is compared against independently materialized finite strings and against the reference kernel (8 coarse prefix bits, matched workspace, row and total-pass limits; if refused, rerun reference with ample space). Historical results before explicit radix stack charging (1,536 additional fixed bytes on 64-bit): workspace 44,288 bytes, cap 32, 14,344 descriptors, 42,904 rows, 14,291 groups, peak 3,957 descriptors / 11,873 rows. Compact: 1 census + 4 distribution = 71,720 descriptor visits, 584,669 local radix digit reads. Reference: 1 + 7 = 114,752 descriptor visits.

Counterexample: the 96-byte homopolymer-family fixture with duplicates admits 1,196 descriptors in 93 censuses + 94 distributions under cap 256, only 19,016 local radix digit reads; the 8-bit reference refuses its 1,184-descriptor coarse bin under matched limits. A tight pass cap should **reject**, not promote this skew. On the two wider-alphabet seeded fixtures compact needed 44 and 21 passes vs reference 16 and 13: fixed plan/histogram overhead can exceed the slot savings on tiny grants. No guaranteed speedup. The oracle verifies finite groups and seams, not a product certificate, physical traffic saving or wall-time ratio. No benchmark, large input arm, constrained RSS/swap measurement or raw-to-product run was performed. Use actual prepared-column censuses, scope the consumer and independent row verifier, then compare matched phases before any promotion.
