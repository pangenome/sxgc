# Ordered audit tee (experimental, prepared resident emitter only)

On Linux x86-64, set `XSA_RESIDENT_ASYNC_AUDIT=1` **in the resident child**, with `XSA_RESIDENT_RADIX_LANES=2..8` and `XSA_RESIDENT_AUDIT_FD` naming the inherited, dedicated verifier pipe writer (>2). The child sets `O_NONBLOCK` on that open file description: do not share it with another writer. Absent the opt-in, or with one lane/no FD/non-FIFO, the sink and optional verifier remain synchronous in their original order. A closed verifier is not a reason to fall back.

END is written to both outputs before data. The ordered join sends one shared reference per packet down a FIFO and writes the same bytes to stdout. Only the last reference can clear and return the original buffer to its originating lane. No row patching, third row buffer pool or on-disk tee. A write error fails the run; a successful write is not a verifier verdict. Require the independent verifier and finish to succeed too. The nonblocking audit writer checks private STOP while blocked and while idle (100 ms polls); sink writes retain their original blocking semantics. Drain and join precede `RESIDENT_STREAM`.

**Accounting (bytes, not RSS).** With `L>1`, `D` dictionary symbols, `m` parse entries, `k` words, `c=sizeof(coord)`, `S=XSA_RESIDENT_RADIX_STEP` (default 16384):

* `retained = 12*(k+1) + (5+2*c)*m + 2*c*ceil(m/16)`. Emit bound = `D + sa_bytes + owner_bytes + retained + 40*k + 8 MiB + extra`. SA is `4D`/`8D` for narrow/wide dictionary; owner is `4D`/`RankStarts::bytes(D)` respectively.
* `extra = ceil(D/S)*(sizeof(Probe)+sizeof(Tile)) + Q + L*3 MiB + 1 MiB + (async ? 2162688 : 0)`. `sizeof(Probe)+sizeof(Tile)=104` on x86-64 (three 24-byte fences and one 32-byte tile). `Q=2*L*65536*12` (6,291,456 B at four lanes). The 2,162,688 B is a 2 MiB writer stack plus 64 KiB control reserve (at most 16 shared blocks and FIFO slots). A single 12-byte END allocation is gone before the lane payloads are allocated. Other phase bounds unchanged; array grant must cover max(parse, aux, dictionary sort, emit).
* Count `Q` against both emit arrays and live scratch, not twice within either. No new scratch files or payload reserve. In the packed full gate: before retirement = sum(packed column sizes) + 8 MiB control + `Q`; finish bound = existing retained parse, pfck, bitmap, sparse, LCP runs, EF spools, pieces, slices, control margin **plus `Q` once**. Check pre-retirement, finish and front-end high-water independently against `2*N`. New stack/control are RAM, not row scratch.

Projected plans **only**, from the committed `gates/receipts/radix-full-1g/parallel` and `packed-serial-10g` censuses. Four lanes, step 16384, serial dictionary kernel, same scratch components. Recompute on the actual inputs; the unmodified harness's front-end `emit_extra` does not include the async reserve. `RESIDENT_RADIX_JOIN.order_wait_s` is ordered lane-receive time (can include credit backpressure); `RESIDENT_STREAM.sink_write_s` is product write + flush time. In the opt-in arm `audit_write_s` is **only synchronous END**. `RESIDENT_ASYNC_AUDIT` reports completed per-branch bytes including END, data bytes excluding END, peak simultaneously shared data blocks (not bytes queued in OS pipes), enqueue time including Arc setup, worker write/poll time, whole worker lifetime, and join/drain wait after the last ordered range. These measurements **overlap**: use `RESIDENT_PHASE phase=emit` for elapsed time; do not add the writer wall, writes or drain to it.

**Reproduce fixtures:** from repository root, `cargo build --offline --release --manifest-path xsa/Cargo.toml -p pfp --bin overlap_resident`; `python3 xsa/pfp/tests/overlap_async_audit.py xsa/target/release/overlap_resident`.
