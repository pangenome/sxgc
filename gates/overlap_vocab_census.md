# Exact vocabulary census (not a front end)

The output is a vocabulary size, packed-extent estimate and two sparse histograms. It is **not** a dictionary, a parse, a global word order, or a suffix sort. There is no measured production speed or IO saving.

**Fixture CLI.** Build `g++ -std=c++17 -O2 -Wall -Wextra -Werror gates/overlap_vocab_census.cpp -o /tmp/vocab-census` and run `python3 gates/overlap_vocab_fixture_test.py /tmp/vocab-census`. In a private fixture directory containing just `corpus`, invoke `/tmp/vocab-census --fixture UNIX_DEADLINE [SEGMENT_BYTES FORCE_ONE_BUCKET POSITION_BASE LOGICAL_SCRATCH_IO_LIMIT]`. Optional controls are all-or-none and can only tighten limits or alter fixture routing/reported positions. Nonempty regular file, no symlink, at most 10,000,000 bytes. Run directory must not already contain `vocab.tmp`. Stop by creating `stop.requested` there (beside `corpus`). Require exit 0 and a complete receipt. On refusal (75) current scratch is cleaned up, never an existing scratch directory. After an external kill discard the run directory.

**Internal seam, not launch authorization.** `--internal-calibrate-10g UNIX_DEADLINE` takes no input, scratch, tuning or output path parameters. Cwd must be `/mnt/nvme2n1/erikg/TAPEREADER/sandbox/vocab-10g-*`, private (owner, mode 0700); its `corpus` must be a singly linked 0400 owner file of exactly 10,000,000,000 bytes. Checks the cgroup v2 CPU, memory and swap settings (one CPU, 192 MiB, zero swap). Checks size and ctime on the same open fd before accepting. The separate parent launcher must attest identity of the private copy, verify exclusive grant, reviewed deadline/window, bank identities, free disk and cold state, observe RSS/cgroup and device traffic, and enforce at phase and block boundaries the absolute cooperative cutoff (no signal to an in-flight sort). This is not a 100GB or arbitrary-path calibration tool.

## Records, grouping and coverage

* Start at 0; for offsets `i=1..N-8` test FNV over the eight bytes at `i` (offset 1469598103934665603, multiplier 1099511628211, mod 2^64 then mod 31). On a trigger, emit raw `[start,i+8)` untagged; reuse the last eight bytes and restart at `i`. Emit `[start,N)` EOF-tagged, even after a trigger on the final window. No seek or reread of raw input. `m` counts these emissions; lengths and starts are checked/reported without truncating corpus positions. The no-trigger case can count the single already-resident EOF record directly.
* Partition by high eight bits of deterministic FNV over full raw bytes followed by tag byte. Scratch input records are `u32(2*len+eof),raw`; count-bearing records insert `u64 f` before `raw`. Native endian, private to one execution. The routing hash is never an equality test. Within a segment sort offsets by `(header, unsigned raw bytes)`, count exact adjacent equals, discarding the segment before creating count-bearing output. Single-segment partitions go directly to the census. Larger ones write **segmented runs**, then merge at fan-in eight. One live candidate per input run; take the smallest header/byte key and add all matching counts before advancing. Final merge counts directly. Comparisons establish only partition-local order. No collision assumption, no repeated rehash of a heavy key.
* Exact scratch invariant assumes private scratch and correct filesystem data: one append per accepted record, size charged including header/count before write, checked writes and flush/close; registered sizes matched to actual extents on read; lengths checked against remaining segment, consumed input retired once. Success requires bytes read = bytes written and zero live bytes. No cryptographic scratch corruption claim.
* Normal word owns its first `len-8` offsets; EOF owns all `len`. For **each distinct** record add 1 to `desc[first*257+second]` at each owned offset, and `f` to `occ` there. `second=raw[next]+1`, including the lookahead at the last normal owned offset; only the last EOF offset has `second=0` (END). Thus last-offset descriptors whose successors lie near trigger boundaries are included, not truncated at the ownership cut. Global END has no raw first byte and is reported separately. Equal finite suffix descriptors share their first two codes (including END where applicable); a cell is indivisible for a two-code cut. Cells need not correspond to single tie groups.
* Groups have positive `f`, `sum f=m`, exactly one EOF occurrence, `sum f*owned=N`. `k` is distinct tagged words, `U=sum owned` over groups. Packed extent `D=U+9k-7`, `tape=D+3k-1` (raw lengths total `U+8(k-1)`, then four packed bytes/word). Output starts with space-separated `key=value` fields; then ascending decimal `cell distinct_count occurrence_count`, skipping zeros. Check histogram sums `U,N`. For interval scheduling add **distinct_count** to get live descriptor load; add **occurrence_count** for conservative expanded scan mass. Not a bound on actual physical reads or sorting time.

## Caps and anticipated work

* One worker, fixed 256 bucket writers with 32 KiB stdio buffers, 64 KiB scan buffer, one word <=1 MiB. Production segments <=32 MiB, never split a record. Each sort holds at most 32 MiB raw and `4*(floor(segment/5)+1)` index bytes (<25.61 MiB); no row pointer per corpus byte. Merge has at most eight <=1 MiB current words (allow 16 MiB vector capacities on libstdc++); no mmap of whole partitions. Two u64 cell arrays occupy ~1.01 MiB. Largest scratch FD count is 256 during scan, 9 during merge, plus raw and stdio. Refuse above 65,536 total created segment files, 8,192 segments/run (including each raw bucket), six merge levels. These bound directory entries **and** in-memory path/segment metadata: only 8-byte `(id,bytes)` stored per segment, plus deques/vectors (at most 8,192 original runs/partition, geometrically fewer next-level runs). Even allowing 2 KiB overhead per run with both adjacent merge levels, metadata is budgeted at 24 MiB. Worker CPU, file cache and allocator overhead are metered together in its actual dedicated cgroup. Working storage plus buffers, stack and library overhead leave substantial room under the 192 MiB grant; file cache is reclaimable, not a measured RSS claim.
* Every counted scratch payload byte, including stdio-pending writes, is precharged against `2N`; deleting a **closed** input segment releases its exact registered bytes. During merge, partially consumed segments remain charged. Missing space for the next entire record means refusal, not a temporary cap exception. This is file-length accounting, not a bound on filesystem metadata, directory blocks, journal, or extent allocation; budget those separately. Immutable private raw and stdout receipt are outside working scratch. Cumulative logical scratch reads+writes <=24N (including spill and all merge levels); one additional N raw bytes. Physical device traffic and locality require separate parent measurement. STOP and absolute wall deadline checked per raw block, segment, and periodically in comparisons/dedup and merge; synchronous IO is not preemptible. Kernel OOM/kill is not a passing receipt.
* For `m>1`: exactly `max(0,N-8)` window tests, eight FNV updates each. Routing reads `N+8(m-1)` raw word bytes plus `m` tag bytes; the first scratch pass writes then reads `B=N+12m-8` bytes. For the **banked receipt's** `m=318164488`, `B=13,817,973,848` (not a new measurement). Each segment with `s` records costs `O(s log s)` key comparisons, each checking lengths/tag then potentially the entire payload. If `S_j` denotes count-bearing bytes surviving run formation or an intermediate merge, total logical scratch traffic is `2*(B+sum S_j)`. Run formation outputs at most `B+8m` bytes, each subsequent pass cannot increase these counts/bytes for the same partition. A bucket with `r` raw segments needs `ceil(log_8 r)` merges after formation (zero for one segment). At each level <=8-way selection and equality checks per grouped key; long shared prefixes and heavy buckets can be expensive. Final accumulation performs `U` descriptor and `U` mass additions, **not** `N` expansions. These are falsifiable operation/byte predictions, not a performance promotion.

## Optional fixed 10 GB component gate

`bash gates/overlap_vocab_gate.sh DEADLINE_UNIX` is a separate, explicitly scheduled **10 GB only** job. It refuses competition, dirty/unpublished source, less than 1,500 s to the deadline, deadlines after the study cutoff, changed scan/front/product/1 GB evidence, incorrect grant, or inadequate space. No starts during the matched product series. Compilation/fixtures and private copy/hash/cold proof are outside the native timer. Native worker cutoff is also ≤1,200 s; a refusal is bankable evidence, not a reason to signal a worker. A distinct subsequent 192 MiB / one CPU / zero swap unit scans the existing immutable packed dictionary sequentially (no eviction of bank files, no cold claim for that verification). No product or 100 GB launch. Run `python3 -BE gates/overlap_vocab_gate_test.py` for the archived-input and fake-meter budget/stop tests, with no large data reads.

Let H=32 MiB, B=N+12m−8, A=B+8m, L=largest verified phrase. Across run formation each original record pays for at most one extra frequency; later merging never increases count-bearing payload. Up to eight partially consumed H-sized input segments can still be live during a merge. Preflight **A+8H+4 MiB** for logical peak incl. a small receipt/control margin; internal pre-write 2N ledger also remains enforced. Report raw copy separately. Each non-last packed raw segment contains ≥H−L−4 bytes, each count-bearing one ≥H−L−12. Charge one partial segment per bucket/run at each level; at most ceil(log base 8 of the worst raw segment count/bucket) merges. Worst cumulative scratch bytes are twice B plus twice A for formation and each nonfinal merge level. At the actual 10 GB dimensions the bounds are **16,635,919,512 / 20,000,000,000 B** simultaneous, 125,815,686,208 B cumulative, 3,444 created segments. Process R/W runaway guards ≤16N each, exclusively measured cgroup plus separate nullable per-device counters. Sampling directory allocation is throttled; it is not the controlling logical peak. `scan_us`, `segment_sort_reduce_us` and `merge_reduce_us` are disjoint inside native wall (close/open and other setup can be outside them); neither phase CPU nor storage seeks are inferred from them.

`overlap_vocab_plan.py` uses actual descriptor/occurrence weights to build contiguous whole-cell ranges. For each descriptor capacity greedily passing the longest feasible prefix gives a minimum number of ranges for this two-code partition; binary search gives the least 8-byte slot payload for a given number of ranges. A failed two-byte bound does not rule out deeper keys. Expanded rows, finite equal-group cursor storage, sampled or dense navigation, and time are separate constraints. The [succinct navigation prototype](../xsa/pfp/OVERLAP_NAV.md) is not in this scanner or a validated full build.

## Independent post-clock comparison

Read the separately banked lexical `dictionary.packed`, not this worker's transient runs: for each little-endian u32 header extract EOF from bit 31 and length from low 31 bits; read that many bytes. Require strict `(bytes,end)` order and exactly one EOF. Apply the owned-offset rule above once per record to an initially zero 256×257 u64 array. Compare every entry including zeros against the sparse output, or hash all 65,792 u64 counts in index order, little-endian, and compare SHA-256 with the bank verifier. Compare `k,U,D,tape`, alphabet and max length. A dictionary alone cannot witness multiplicities: compare *every* `occ` cell against the separate raw scanplan-10g witness (or independently count packed parse IDs and reweight the packed words after clock). Raw starts/high positions come from the raw scanplan witness. Bind exact inputs and receipt identities before any real comparison. In the same post-clock tape pass, a separate wire-size ledger uses adjacent raw LCP and periodic restarts to count the payload/directory/literal/maximum-block bytes for the [4/8/16-word compressed dictionary fixture](../xsa/pfp/LEXICAL_BLOCKS.md). This does not time the random-access codec, build a compressed dictionary at 10 GB, or change the raw candidate's clock. `model.json` distinguishes exact wire bytes under that encoding from modeled navigation/phase capacities and an unmeasured 10× sensitivity.
