# Matched 10 GB raw-to-v8 scaling measurements

Preparation only, once, on an idle host: provide a clean standalone checkout at
`8513cccb7d0ade1f4917752e3e8be33c3f7e49e3` (imports the `7f6fdcd`
OpenMP producer and `2cea580` reclaim sink), and a **nonexistent** private
tools directory outside both repositories. Do not modify either checkout or
tools during a series. Run from a clean committed harness.

```
bash gates/overlap_ten_product.sh --prepare-tools "$PINNED_REPO" "$TOOLS"
```

Separate, explicitly scheduled arm (never a sweep):

```
bash gates/overlap_ten_product.sh --profile packed-10g-l1-b0-t1-r0 "$PINNED_REPO" "$TOOLS" "$DEADLINE_UNIX"
```

Use exactly `packed-10g-lL-bB-tT-rR`: L = radix lanes 1/2/4, B = sink
batched escapes 0/1, T = selected dictionary threads 1/2/4, R = private
sink marker reclaim 0/1. The same `CC=gcc XSA_BUILD_DICT_OPENMP=1`
binaries serve all 36 combinations, including serial-batch. An explicit T=1
uses the serial dictionary API in that binary. This is **not** the historical
serial binary. The no-argument launcher remains the original arm. Neither
its operator schedule nor already running jobs are changed. Do not start any
other timing job: matched launches share a nonblocking per-user lock and
probe for running gate harnesses/workers; unrelated/legacy launchers cannot
be prevented from starting later. Do not use the Python worker CLI as a
launcher. `DEADLINE_UNIX` is positive integer seconds since Unix epoch UTC,
not a duration. It refuses a late timing launch, and requests cooperative
stop during front, resident/finish and oracle. Not a SIGKILL timer: copies,
kernels without a poll and post-run checks can outlast it. A flagged/partial
run is not scoreable. No recovery from partially consumed slice metadata.

Same private non-reflink copies, mincore zero-page checks (including cold
transition after front), row43 verifier, frozen finish/remap, nine-member
product SHA, 200 GiB build/140 GiB array grant, 4 CPU quota and 14000 MiB /
1 CPU oracle; no swap. Keep existing NVMe vs private tmpfs placement and
reserve all RAM/scratch even when markers are reclaimed. Only sink gets the
reclaim opt-in, only for R=1 in fresh non-spooling mode. Check exact marker
pairs in private tmpfs after both workers exit: for R=1 exactly last 64
slices (128 markers); for R=0 all 38,147 pairs. Sampled peak piggybacks on
existing scans; not a continuous or atomic dentry trace. Empty marker inode
and kernel cache memory are not file bytes. Build controller CPU uses its own
process clock (through timed build, excludes later cleanup); worker and
oracle CPU are separate. Where `io.stat` exists, report per-device cgroup rbytes/wbytes
deltas without summing potentially stacked devices; missing snapshots give
null, not zero. No hardware locality or system-wide IO claims.

After **both** arms have exited and certified:

```
python3 gates/overlap_ten_matched_score.py single-knob "$CONTROL" "$TRIAL" "$OUT_JSON"
python3 gates/overlap_ten_matched_score.py historical "$OLD_SERIAL" "$TRIAL" "$OUT_JSON"
```

The first requires exactly one changed knob, same build hashes, harness
revision, CPU affinity, grants, row summary and complete product identity.
The second accepts only the pinned historical `02da5de` producer/sink pair;
that sink predates `SS_SXLS_WRITER`. All other executable and remap hashes
must match. A cross-revision combined delta cannot be attributed to a knob.
Raw/prepared/phase wall ratios and worker-attributed raw/prepared IO ratios
are reported separately (trial/control, lower is better), with no speed-based
identity verdict. No result here is an automatic promotion or larger launch.

Keep the arm's `build.json`, `front-end.json`, `oracle.json`, `identity.json`,
`scratch-plan.json`, `binaries.sha`, `exits.log`, `cold.log`, `resident.log`,
`oracle.log`, and for new arms `build-source.log`, `seam-fixtures.log` and
`sink.log` (or `sink-metrics.log` retaining both `SS_SXLS_WRITER` and any
`SS_PRIVATE_SXLS_RECLAIM` lines). Keep `fixtures.log`, `pack.log`, finish
metrics including bitmap events, and `goals.json` for independent review.
The matcher uses receipts rather than rereading a banked multi-GB product;
identity must be generated by the original actual product verifier. Keep a
reference to each full original receipt. No production or 100 GB evidence is
implied by the small tests: `python3 gates/overlap_ten_matched_test.py`.
