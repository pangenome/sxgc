# 10 GB exact vocabulary and independent lexical-tape check

`proc_bebf`, private `vocab-10g-CsiXpF`, pinned `1fdfcf5`, both services exit 0. `python3 -BE gates/overlap_vocab_review.py gates/receipts/vocab-10g` replays [the review](review.json) from the small receipts, including [every occupied cell](census.out); no corpus/tape reads. Original file digests, tool hashes and source in [source.json](source.json). **This is not a lexical front, suffix order, container or product speedup.** It did not assign word IDs, create a text-order parse or build a compressed dictionary.

**What changes for a bounded orderer.** Largest two-symbol cell (`e`, space): 212,471,462 distinct descriptors / 231,078,052 expanded rows. Minimum unsplit 8-byte descriptor payload **1,699,771,696 B**; 256 MiB and 1 GiB still refuse, 2/4 GiB give **38/18** whole-cell ranges (vs 42/20 from occurrence mass alone). These do not include the tie heap. Actual matching 10 GB producer measured *largest complete finite-key group* **546,042** list descriptors, not 212 million. At 20 B/cursor, that group alone would require 10,920,840 B without rank windows or at least 67 windows at 8,192 cursors (not a measured window count). [model.json](model.json) has the full ranges, normalized wire counts and phase models.

**Measured wire ledger; modeled fit.** Adjacent-word prefix coding with literal restarts every 4/8/16 words would take **9,255,908,745 / 8,604,165,576 / 8,278,299,754 B** payload + block directory on this exact tape. These are counts from the independent packed-tape pass, not timed random access to an encoded corpus. At *10× the measured 10 GB dimensions/density*, block-16 + sampled navigation models 115,656,818,596 B before order, leaving **34,667,036,764 B** of the 140 GiB comparison. No large compressed loader, allocator/paging/order/consumer or throughput proof. Four-k wide parse workspace models 138,664,168,960 B; six-k 176,179,804,640 B. Only `m`, not `k` or lexical compression, has been measured on the actual 100 GB text.

**Don't extrapolate this timing linearly.** At the measured 100 GB `m`, first-pass records alone would occupy 138,176,013,848 B. Across 256 buckets of 32 MiB segments, some bucket needs ≥17 segments and thus ≥2 eight-way merge levels; ≥69,456,537,112 raw record bytes belong to buckets needing multiple levels. That is not a lower bound of that many *additional* physical writes after dedup. No 100 GB vocabulary or product dispatch from this result.
