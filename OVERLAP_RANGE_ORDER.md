# When the dictionary fits but its wide SA does not

`xsa/pfp/src/overlap_range_order.rs` is a standalone ordering kernel. There is no producer switch. Choose it for study only if the encoded bytes **and** word starts/frequencies are charged as resident, the full dictionary SA is unaffordable, and the pass count and skew fit explicit caps. Do not use it to follow pointers into a cold mapped dictionary. It requires neither a prior SA/interval plan nor a file of suffix strings. Run just the oracle from the repo root:

```sh
rustc --edition 2021 -Dwarnings --test xsa/pfp/tests/overlap_range_order.rs -o /tmp/overlap_range_fixture
/tmp/overlap_range_fixture
```

`order(&dictionary, limits, callback)` validates the resident encoding (SEP=0, END=1, increasing u64 starts including end). Word IDs are indices into actual metadata, not a census constant; descriptors are two `usize` on a 64-bit host. Given valid PFP columns and aligned occurrence counts, enumerate offsets before the final eight overlap symbols (EOF: before END). Thus every owned tail has at least two symbols. Bucket by the leading `prefix_bits` (1..16) of its first two bytes in big-endian order. A histogram counts exact descriptors **and** rows (one word frequency per descriptor, checked u64 sums). Pack consecutive whole bins greedily, cutting before either limit would be exceeded. In-place comparison sort within each resulting range compares finite byte slices excluding SEP, including terminal END. Prefix projection is monotone, so concatenation is exact and a tie cannot span bins or ranges. The kernel does not validate parse edges or the PFP no-proper-prefix theorem; finite order alone is not a row-order proof for arbitrary segmentations.

The callback borrows one complete equivalence class of `(word,offset)` list selectors. The first LCP is zero against global END, otherwise the common prefix with the previous distinct finite key, **not reset at a range cut**. Emit global END separately. Within the class interleave occurrences by successor rank, not descriptor order; internal adjacent row LCP is `finite_len - overlap + aligned_successor_lcp` for nonfinal ties. Consumer handles text positions, predecessors and row transport. The fixture checks finite keys against independently copied tails and exercises that interface against brute suffix positions/LCP of a small overlapping text. It does not build lists, aligned RMQ or a container for production.

**Accounting.** With `k` words, `D` encoded bytes, `U` owned offsets, `H=2^prefix_bits` bins, `A` peak range descriptors, `B` admitted ranges, and maximum word length `L`, the additional heap *payload* on a 64-bit host is `16H + 16A` bytes. Set `workspace_bytes` after charging `D + 8(k+1) + 8k` resident input bytes, consumer/list/heap/queue lifetimes, allocator slack, stack (sort O(log A)), other processes and safety margin. `try_reserve_exact` requests once per array, then reuses the arena. No durable scratch. Row mass is a work limit, not an estimate of cursor bytes. Budget the consumer independently (in particular up to A simultaneous list cursors). These are not RSS or physical IO measurements.

One validation pass over `D`, one full physical-word-order classification pass, then **one more classification of every owned offset per range**, even ones not routed to that range. Logical pass cost `(1+B)(k+U)` plus validation, not `U` total visits. Histogram planning O(H). Additional worst-case byte comparison work O(U L log(2+A)), including grouping/seams. This cost can dominate on long common prefixes; cached sequential distribution is not the access pattern of the pointer sort. Before selecting a pass cap, even without skew, `B >= ceil(16U / (workspace_bytes - 16H))` for positive arena capacity; independently `B >= ceil(total_rows / rows_per_range)` for positive row cap. The 1 GB archived U=938,179,281 implies **at least 14 distributions** at 1 GiB workspace even before skew. These are in-memory traversals, not device reads. Unlike the [8-byte-ref estimate](OVERLAP_SCALING.md), this layout does not presume a narrow word ID or local offset.

Set `distributions` to the maximum tolerable extra full passes. An overfull bin returns its prefix index and exact load before any callback; excess passes return the required count. A heavy bin might contain many *different* keys: this version refuses, it does not assume the entire bin is one unsplittable tie. For example, two `zz` descriptors with mass 24 in the fixture cannot enter a two-byte-prefix range of mass 23 even though 8 descriptor slots fit. More bits help only up to 16; refining deeper or spilling keys is not an implicit fallback. If the corpus/resident metadata do not fit, an irreducible equal class exceeds the consumer grant, or the estimated distributions already cost too much, **do not launch**. No 100 GB fit, time, physical traffic, <3× or product claim; only bounded fixtures tested.
