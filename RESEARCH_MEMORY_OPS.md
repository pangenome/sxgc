# A small operation set for interrogating a corpus

Research memo, 2026-11-10. Proposal, not an implementation or a new performance claim.

The useful abstraction is a **phrase locus plus an explicitly scoped set of documents and evidence spans**. Keep seven operations: **seek, extend, relax, project, select, matches, read**. Rarity, similarity, ranking and context assembly are compositions of these operations, not new index structures. The closest prior art for the observed semantic neighbourhood is phrase-based suffix-tree document similarity, especially Chim and Deng (2007); maximal-match algorithms supply the evidence, not a theorem that evidence implies meaning.

## Literature: what it establishes, and what it does not

**1. Phrase clustering and similarity.** Zamir and Etzioni's *Web Document Clustering: A Feasibility Demonstration* (1998) makes shared consecutive word sequences into suffix-tree base clusters, then merges overlapping document groups. It demonstrates useful, readable phrase clusters; preprocessing, scoring and merging are algorithmic choices, not semantic guarantees. Chim and Deng's *A New Suffix Tree Similarity Measure for Document Clustering* (2007) is even closer: documents become vectors over shared suffix-tree nodes, with node term frequency and document frequency feeding a tf-idf weight and cosine similarity. Their experiments support phrase features for topical grouping. Neither paper says that a raw count of byte MEMs is a universal semantic metric. **Build on:** phrase loci, document incidence and weighted comparison. Do not import their clustering thresholds into the primitive API. [Zamir and Etzioni, 1998](https://homes.cs.washington.edu/~etzioni/papers/sigir98.pdf); [Chim and Deng, 2007, §3.2](https://www2007.cpsc.ucalgary.ca/papers/paper091.pdf).

**2. String kernels.** A kernel is a similarity that can be expressed as an inner product in a feature space. Lodhi et al.'s *Text Classification using String Kernels* (2002) counts common ordered subsequences, allowing gaps and penalizing their extent: it is not contiguous exact matching. Leslie, Eskin and Noble's *The Spectrum Kernel: A String Kernel for SVM Protein Classification* (2002) uses counts of exact contiguous length-k strings; Leslie et al.'s *Mismatch string kernels for discriminative protein classification* (2004) permits bounded substitutions in those features. Fixed k, mismatch allowances and decay factors are model choices. Vishwanathan and Smola's *Fast Kernels for String and Tree Matching* (NIPS 2002) and Teo and Vishwanathan's *Fast and Space Efficient String Kernels using Suffix Arrays* (2006) give the more relevant all-substring route: annotated suffix structures can evaluate suitable weighted substring kernels efficiently. **Build on:** exact substring feature maps and compressed aggregation. Their linear-time algorithms require their annotations and weight assumptions; they do not make arbitrary pair-dependent MEM selection a positive-semidefinite kernel or prove semantic relevance. [Lodhi et al.](https://jmlr.org/papers/v2/lodhi02a.html), [spectrum](https://cseweb.ucsd.edu/~eeskin/papers/spectrum-psb02.pdf), [mismatch](https://doi.org/10.1093/bioinformatics/btg431), [fast kernels](https://papers.nips.cc/paper_files/paper/2002/hash/743394beff4b1282ba735e5e3723ed74-Abstract.html), [suffix-array kernels](https://users.cecs.anu.edu.au/~chteo/pub/TeoVis06.pdf).

**3. Maximal matches and sequence similarity.** A pairwise MEM is a matching pair of substrings that cannot be extended at either end for those two occurrences. A MUM additionally requires uniqueness in the specified sequences; MUMmer distinguishes uniqueness in the reference from uniqueness in both sequences. Kurtz et al.'s *Versatile and open software for comparing large genomes* (2004) uses exact matches as alignment anchors, followed by clustering/extension. Ulitsky, Burstein, Tuller and Chor's *The Average Common Substring Approach to Phylogenomic Reconstruction* (2006) instead aggregates longest-match lengths at each position, connecting matching statistics to sequence distance. These are concrete precedents for variable-length match evidence, not natural-language relevance results. A maximal repeat is a repeated string with differing extension contexts, useful as a compact feature candidate; it need not cross documents. **Build on:** exact enumeration, matching statistics and coverage. Searches for MEM/document-similarity/IDF found no verified paper establishing the precise recipe “sum IDF-weighted byte MEM counts” as the desired semantic metric. Chim and Deng supply the adjacent phrase-tf-idf precedent; do not rename it a MEM theorem. [MUMmer](https://pmc.ncbi.nlm.nih.gov/articles/PMC395750/), [average common substrings](https://www.cs.tau.ac.il/~bchor/ACS.pdf), [Gusfield's 1997 algorithms and implementation reference](https://www.cs.ucdavis.edu/~gusfield/strmat.html).

**4. Frequencies without expanding every substring.** Yamamoto and Church's *Using Suffix Arrays to Compute Term Frequency and Document Frequency for All Substrings in a Corpus* (2001) is the direct foundation for arbitrary phrase statistics. Substrings along an unbranched suffix-tree edge share occurrence starts and hence document statistics, so one can represent frequency equivalence classes without printing every string. This does not remove the quadratic output size if every distinct substring must actually be spelled out. Muthukrishnan's *Efficient algorithms for document retrieval problems* (2002) gives document listing in O(pattern length + distinct documents) with its auxiliary structures; Sadakane's *Succinct data structures for flexible text retrieval systems* (2007; preliminary version 2002) supplies compressed structures for arbitrary-pattern listing and tf-idf scoring. **Build on:** exact projection and df. A document-boundary map alone does not inherit those output-sensitive bounds, and an occurrence count is not df. [Yamamoto and Church](https://aclanthology.org/J01-1001/), [Muthukrishnan](https://www.researchwithrutgers.org/en/publications/efficient-algorithms-for-document-retrieval-problems/), [Sadakane](https://doi.org/10.1016/j.jda.2006.03.011).

**5. Variable-order prediction.** Rissanen's *A Universal Data Compression System* (1983) selects informative variable-size contexts. Cleary and Witten's *Data Compression Using Adaptive Coding and Partial String Matching* (1984), the origin of PPM, backs off among context orders with escape probabilities. Willems, Shtarkov and Tjalkens's *The Context-Tree Weighting Method: Basic Properties* (1995) mixes predictions over bounded-memory binary context trees with finite-sequence redundancy bounds relative to the source class. CTW does not simply choose the longest match or one magic depth; the basic method has a maximum depth and a model prior. **Build on:** branch counts and suffix-context backoff; use predictive code length or a declared support criterion to choose depth. Neither compression bounds nor “longest observed” imply sufficient evidence for a research conclusion. Adapting CTW to bytes and a static, filtered corpus requires explicit probability estimates, alphabet handling and model assumptions. [Rissanen](https://research.ibm.com/publications/a-universal-data-compression-system), [PPM](https://doi.org/10.1109/TCOM.1984.1096090), [CTW](https://pure.tue.nl/ws/portalfiles/portal/1383848/Metis122608.pdf).

**6. Literal distributional semantics.** Harris's *Distributional Structure* (1954) grounds linguistic analysis in relative occurrence; Schütze's *Word Space* (1992) demonstrates semantic representations derived from distributional evidence. The “company it keeps” idea can be operationalized without learned dense embeddings: a phrase's company is its document-count vector, or its exact left/right continuation distribution. Two phrases with no common bytes can still have similar document distributions. That is a second-order association, distinct from documents directly sharing phrases. **Build on:** auditable incidence and count distributions, then an explicit similarity function. This is a testable representation choice, not a proof that document co-membership equals synonymy: antonyms co-occur, quotation copies text, and identical strings can have multiple senses. Schütze's learned/reduced representation is precedent for distributional reasoning, not an exact-match-only implementation. [Harris](https://doi.org/10.1080/00437956.1954.11659520); [Schütze](https://papers.nips.cc/paper/1992/hash/d86ea612dec96096c5e0fcc8dd42ab6d-Abstract.html).

**7. Boolean and positional retrieval.** Suffix intervals provide arbitrary-phrase postings once projected to document IDs and offsets. Document intersection implements AND; intersection of raw suffix intervals does not, because different phrases generally start at different positions. Clarke, Cormack and Burkowski's *An Algebra for Structured Text Search and a Framework for its Implementation* (1995) gives interval operations including containment and ordered combination, with searches over explicitly or implicitly marked regions. **Build on:** document-set operations and positional joins to shape evidence regions. Document co-occurrence alone does not prove adjacency, order or membership in the same section. Section-aware retrieval requires section boundaries; a suffix tree cannot infer those semantics. This is a direct theoretical basis for “near” meaning same document, same supplied region or ordered occurrence, rather than an arbitrary byte window. [Clarke et al.](https://doi.org/10.1093/comjnl/38.1.43), [author technical-report version](https://cs.uwaterloo.ca/research/tr/1994/30/structxt.pdf).

**8. Exact text and language-model memory.** Liu et al.'s *Infini-gram: Scaling Unbounded n-gram Language Models to a Trillion Tokens* (2024) provides suffix-array counting and next-token distributions with variable-length backoff at very large scale; its engine also supports Boolean document search. Liu et al.'s *OLMoTrace: Tracing Language Model Outputs Back to Trillions of Training Tokens* (2025) is a close practical match: maximal verbatim spans lead to enclosing documents. It imposes sentence/word boundaries, filters using unigram probability, samples occurrences and reranks with BM25. Thus its ranking is neither pure MEM counting nor phrase-df weighting. **Build on:** exact evidence retrieval and controller-visible continuation statistics. Neither system establishes a complete controllable-memory lifecycle: durable selected evidence, revision/invalidation, deliberate scope changes, writeback and evaluation of controller decisions remain design work. Verbatim overlap is not causal proof that a training document produced a model answer. [Infini-gram paper](https://arxiv.org/abs/2401.17377), [engine](https://infini-gram.io/), [OLMoTrace, §3](https://arxiv.org/html/2504.07096v1).

## The seven operations

### State and cost vocabulary

A locus is `(snapshot, l, r, depth)` with half-open suffix-array interval `[l,r)` and exact byte depth. Keep an edge-label reference or recoverable phrase as well. Equal intervals at different depths are different states: their next bytes may differ. A scope is an immutable document-ID set, initially all documents, optionally carrying allowed positional regions. A result identifies its snapshot, scope, boundary policy, count kind and completeness. Byte matching is the default; any tokenization or normalization creates a separately identified text view.

Let m be pattern length, w interval width, k outgoing labels, z emitted match records, h examined occurrences, d distinct output documents, and B bytes read. Let R be one rank operation, F one LF step, C one exact child/edge transition, P one exact parent/enclosing-interval step, S one suffix-link/drop-left step, A one text/edge-byte access, and U one document-boundary lookup (binary search gives O(log D), with D documents). Let `Loc(h) = sum_i LF_steps(i)*F + O(h)` for current sampled-SA location. No short LF-distance bound follows from sampling every 1024th run. LCP/rank navigation costs remain symbolic until implemented and measured.

The following are semantic primitives. Optional modes are views of the same relation, not permission to hide different costs.

| Operation and one-line definition | Input → output | Tree/rank work and unavoidable work | Why generic; grounding |
|---|---|---|---|
| **seek**: resolve exact bytes to their locus. | Bytes P → locus or empty. | Current backward search: at most 2m ranks, O(mR). With labelled tree: O(m) edge-byte checks plus traversals. | Any bytes and any length; no seed/window constant. Exact suffix search, Gusfield (1997). |
| **extend**: inspect or choose the next exact continuation. | Locus, side, optional byte, scope → labelled child loci and scoped counts, including boundary mass. | Right: O(kC + kA) with an output-sensitive children layer; a chosen byte costs one C with a child dictionary. Current fallback searches P+b, O(alphabet_size*mR). Left: two ranks per chosen byte, but scoped counts require project. | Choice follows actual branches, including unary edges. No learned parameters. Suffix-tree partition invariant; predictive use grounded in PPM/CTW. |
| **relax**: remove constraints from one end of a phrase. | Locus, side, number of bytes or next support-changing ancestor → shorter locus. | Drop right: depth adjustment within edge, then P per crossed parent. Drop left: S per step with suffix links, otherwise seek the retained suffix. Support stopping additionally pays project for each probe. | Exact shortening, or caller-selected support target; no fixed context length. Monotonic containment and context backoff. |
| **project**: turn phrase occurrences into document evidence. | Locus, scope, requested view → `(doc_id, tf)`, exact df, optionally offsets/intervals. | Baseline: enumerate w rows, `Loc(w)+O(wU)`, filter boundaries/scope, aggregate; sorting costs if ordered output is requested. Document-array/range-count indexes can avoid occurrence enumeration; not assumed present. | Counts all occurrences or documents under a stated predicate; no cap silently changes df. Yamamoto–Church, Muthukrishnan, Sadakane. |
| **select**: combine evidence by document or positional relation. | Sorted evidence sets, relation (AND/OR/EXCEPT/within/followed-by), optional scope → scoped evidence set. | No new ranks once materialized. Document merge O(a+b); sorted positional sweep O(a+b+output) for simple joins; sorting O(h log h) if necessary. All pair outputs can be quadratic. | Relations express a research question; proximity distance only if supplied explicitly. Boolean retrieval and Clarke et al.'s interval algebra. |
| **matches**: enumerate maximal exact evidence between a query and a declared target scope. | Query bytes, scope, maximality mode → query intervals plus target loci or occurrence pairs. | Full navigable suffix tree: matching-statistics scan O(m(C+S+A)) plus output/verification. Current corpus-global MEM path: O(m*Lmax*R), Lmax ≤ m. Scoped support adds project calls; pairwise output pays location and can be enormous. | Ends determined by mismatch, scope or document boundary, never a fixed window. MUMmer/average-common-substring literature; distinguish modes below. |
| **read**: materialize chosen evidence with provenance. | Document ID and explicit `[start,end)` or supplied region ID → exact bytes, coordinates and snapshot identity. | O(B) byte access after bounds validation; if starting from a locus, project/location is separate. Without retained text, charge index extraction/navigation explicitly. | The reader/controller chooses evidence extent; no automatic 1024-byte halo. Structured text intervals and ordinary verified byte extraction. |

The document map must enforce boundaries even though today's byte index treats separator `0x1E` as ordinary searchable data. Accept an occurrence only if its whole span lies inside the selected document/region. This makes scoped tf potentially smaller than raw `r-l`; cache neither as the other. At document ends return END mass separately. For extend, scoped child counts plus END must equal the scoped parent count. Empty seek is a root/navigation state; reject it for ranking features and MEM enumeration. Preserve UTF-8 byte offsets without pretending every byte span is a complete word.

**Two kinds of maximality must be named.** `matches(mode=corpus)` returns query spans for which neither query-side extension occurs anywhere in the target scope; this is the existing serving definition. `matches(mode=pairwise)` returns occurrence pairs unextendible at those particular coordinates. A phrase extendible in document A can still be a pairwise MEM in B. Corpus-global MEMs therefore cannot substitute for all per-document MEMs. For correctness-first scoped matching, test each extension using project restricted to scope; expensive, but exact. A faster restricted document index or range-count layer is a later optimization. Never enumerate globally and merely discard excluded documents afterward: exclusion can change maximality itself.

**What was cut.** “Ascend for support” is relax plus project; “descend for specificity” is extend plus project. Occurrence location is a project view rather than a second operation named locate. Distribution comparison, rarity weights and document ranking are client arithmetic over project/extend outputs. Context assembly is select plus read, with saved provenance. These do not warrant separate persistent index structures. Matches remains a primitive because repeated fresh seeking loses the shared traversal needed for a whole-document scan; read remains because a histogram cannot supply the source text a controller needs.

## Compositions that make this a memory interface

**Rarity and document ranking.** For phrase p in a fixed reference universe U, use `idf_U(p) = ln(|U|/df_U(p))` when df is positive. df is the number of documents containing p; tf(p,d) counts occurrences in one document. Repeated hits in one document must not masquerade as independent document support. Today's `max(0, ln(D/occurrences))` is a lower-bound surrogate for IDF, not exact IDF. Freeze U while interactively filtering candidates, or explicitly label local rarity; otherwise scores change meaning after each filter.

A transparent baseline for a fixed distinct phrase basis F is `score(q,d) = sum_{p in F shared by q,d} idf_U(p)`. It is a binary shared-feature score, not a raw MEM-occurrence count. Its attribution list is exact; topical effectiveness remains empirical. If the same F and nonnegative weights are used for every document, the weighted incidence inner product is a valid kernel (features are `sqrt(idf)*presence`). Query-specific maximal features produce a retrieval score but not automatically a symmetric kernel. Cosine normalization can reduce document-size effects; state its feature universe and norms. It is not free if those norms require enumerating every substring.

Overlapping seeds can give one copied sentence hundreds of votes. Also report query coverage, the length of the union of matched query intervals divided by query length. For an optional overlap-resistant score, integrate the maximum IDF of any contributing span at each query byte and divide by query length. Compute by sorted endpoint sweep with a maximum-weight active set, O(z log z); no byte-by-byte expansion is necessary. This is a proposed scoring policy, not a published semantic theorem, and it favors evidence coverage differently from distinct-phrase scoring. Do not silently switch policies to obtain an attractive ranking.

**Compare contexts.** Normalize project counts into document distributions or extend counts into next-byte distributions. Compare sparse vectors by cosine, or use Jensen–Shannon divergence (the mean relative entropy to their average). Zero-support states return “no evidence”, not similarity zero disguised as a measured distribution. Different axes answer different questions: shared documents suggest a topic; shared continuations suggest substitutability in a local syntactic position. None requires learned embeddings.

**Choose depth.** For phrase exploration, extend while retaining the requested document support; relax until support returns. A threshold is a caller's evidence requirement, not a corpus-specific constant. For online prediction, use suffix backoff: remove the oldest byte, not the newest. The suffix-tree parent removes a trailing segment and therefore is not the PPM context parent. Counts can drive a declared predictive-code-length policy or a CTW-style mixture; neither belongs inside the navigation primitive. The parameter-free primitive contract does not mean every useful controller policy is parameter-free.

**Shape and remember context.** Seek a phrase, inspect continuations, project to candidate documents, select the documents sharing another phrase, then project positions within one chosen document. Read exactly the matching spans, their minimal enclosing interval, or a supplied paragraph/section. Without structural metadata, expose exact coordinates or the whole document as explicit choices; do not invent sentence boundaries or a proximity window. Store a context record containing snapshot hash, selected doc IDs/ranges, original query, operation trace, score policy, evidence completeness and any controller-written note linked to those ranges. Selecting another context changes this record, not model weights. Replay verifies bytes and scope; new corpus versions invalidate or re-resolve references. Appending notes/new documents requires a separate versioned ingest/write API: a static suffix tree is not itself a writable memory store. This lifecycle is proposed architecture, not a claim that retrieval alone solves memory.

## The cats case: mechanism and deliberate reproduction

Rare exact phrases preserve multiword entities, specialised terminology and copied descriptions. Cat-related articles share more such strings than unrelated articles; weighting their document incidence suppresses generic language. Shared text can therefore induce a strong topical neighbourhood without a learned semantic coordinate system. This is the mechanism supported by phrase clustering and string features. It also predicts the observed false positives: quotations in noticeboards are genuine matches; markup fragments can be rare and still irrelevant. Rarity measures specificity to the corpus, not truth or useful subject matter.

There is a crucial self-match trap. If the Cat query is already a corpus document, its whole body matches itself. Corpus-global MEM extraction can collapse to that one match, hiding shorter phrases shared with other documents. Removing the source only at the final ranking stage cannot repair this. Exclude the source **during maximality tests**, or use per-document MEMs, or relax each matching-statistics prefix to the longest prefix shared by at least two distinct documents including the source. The last method is an adaptive shared-phrase basis, not strictly corpus-global MEM enumeration. Occurrence multiplicity two is insufficient when both copies occur in Cat.

A reproducible experiment should:

1. Pin the Wikipedia snapshot, document map, byte view and source Cat body; record its actual ID and exclude that ID before scoped matching. A focused `domestic cat` phrase exploration is a different query and gets a separate receipt.
2. Enumerate scoped corpus MEMs for a first fast baseline, and a complete pairwise-MEM reference on a manageable candidate subset. For broader recall, enumerate the longest shared prefix at each Cat position with df ≥ 2 in the universe including Cat, then remove duplicate phrase strings. There is no maximum byte length. This basis can miss shorter evidence in other documents; inspect shorter support-changing ancestors or use pairwise enumeration when completeness is required.
3. Project the phrases to exact df and per-document counts. Score with the declared distinct-phrase IDF baseline; report overlap-resistant coverage alongside it. Use a fixed tie break by document ID. Retain each contributing phrase and both sets of coordinates. Keep raw text and an explicitly defined prose-region view as separate runs; markup removal is preprocessing, never a generic primitive.
4. Include Domestication of the cat, Cultural depictions of cats, other cat articles, noticeboard quotations and unrelated controls. Report raw shared counts, true df versus occurrence-based weights, coverage and candidate completeness. Use select/read to inspect which passages caused each rank. Compare the exact original fanout flags separately; its 256-seed cap, length caps, occurrence samples and 2000-byte region gap are historical policy choices, not this API.
5. Require matching and count equality against brute-force small fixtures; evaluate topical ranks separately. Do not define success as forcing Domestication of the cat to rank first. If its proposed rank differs, publish the evidence and scoring differences. The mechanism makes that result plausible; the checked-in evidence does not establish its cause or its first-place status.

The operation set deliberately reproduces **auditable exact-evidence ranking**, not a promised order of titles. A semantics benchmark must distinguish topical relatedness from copied-text similarity, use more than cats, and include paraphrases with little surface overlap. No retrieved paper guarantees the owner-reported ranking for this byte corpus.

## What to build first

The highest-return three operations are **extend, relax and project**, layered on existing seek, MEM and text access. They turn the stateless query core into controllable exploration; select and ranking initially need only client-side sorted-set arithmetic.

1. **Extend with exact child labels/counts and reusable loci.** Publish `(l,r,depth)` including implicit edge positions. Require a real boundary finder over the new LCP representation and a label accessor. A plain scan costs O(w) LCP inspections plus label accesses; do not call it O(k). A range-minimum/navigation structure or exact child directory is needed for output-sensitive splitting. Run-boundary LCP samples alone are not enough unless their reconstruction/navigation contract proves it. Verify unary states, root, END, absent bytes and arbitrary document boundaries against fresh search.
2. **Relax with explicit left/right semantics.** Parent/enclosing-interval navigation supplies phrase generalization; suffix links or an explicit fallback seek supply drop-left predictive backoff. This needs more than children alone. Initially allow the correct slow fallback, expose its cost, and optimize only after measuring. Verify support monotonicity, implicit-depth changes and a case where dropping left differs from taking the tree parent.
3. **Project with exact counts and paged evidence.** Start with current locate plus document-boundary lookup for narrow intervals, exposing actual LF work. Use resumable streams, bounded queues and a bounded accumulator or disk spill for large document sets. Compute exact totals only after complete enumeration; otherwise report a lower bound plus cursor, never exact df. Measure whether a document array, wavelet-tree range counting, or Sadakane-style structure is justified before committing large persistent space. LCP and children alone do not accelerate this bottleneck.

Every response should carry an exact/partial flag, cursor and examined-work counters. Pagination is a resource contract, not a hidden sampling algorithm. Pin requests and cursors to the same snapshot. Cap outstanding work and caches, apply backpressure, and avoid retaining results proportional to all processed positions—the extraction note's memory failure is exactly what this interface must prevent. This memo does not claim 150,000 positions/s; qualify warm/cold latency, RSS and real consumer traces before making such a promise.

### Build acceptance, not performed in this research task

Use a small independently searched corpus with duplicates, repeated phrases within one document, separated documents, binary bytes, unary tree edges and empty/absent queries. Check full occurrence lists, df versus tf, scoped child closure, left/right relaxation, pairwise versus corpus-global maximality, source exclusion before matching, and exact read provenance. Compare stateless requests with replayed cursor operations. Separately measure wide-interval projection and children, and long-document MEM enumeration; the existing quadratic scan is not a viable assumed linear implementation. Then run the cats ablations with complete receipts. No product tests or corpus benchmarks were run for this documentation-only change.

## Review and residual risks

Primary papers, proceedings pages and author-hosted manuscripts were checked through web search on 2026-11-10; search-result crawl dates were not used as publication years. This is a focused literature investigation, not a systematic proof that no MEM-IDF work exists. Closest precedents are identified with their actual distinctions. The proposed operations are exact relations; semantic ranking, useful depth selection and controller memory policy remain empirical design questions.

Unresolved engineering costs are scoped document statistics, compressed child/parent/suffix navigation, label extraction and worst-case match output. A buildable slow baseline exists, but production throughput and extra structure size remain unmeasured. The Domestication-first result lacks a verified receipt here. The two prerequisite studies were read from other committed branches because they are absent on the pinned main. No supervisor coordination tool was exposed: metadata discovery for `contact_supervisor`, `supervisor` and `intercom` returned no tools; no supervisor decision is claimed.
