\begin{abstract}
Suffix indexing, substring frequencies, and rarity weighting are established ideas; our contribution
is measured scale and cost. On the first $\qnum{input}{10^{11}}$ bytes of the Pile, a
bounded-resource tape pipeline builds a $\qnum{container}{63{,}163{,}489{,}696}$-byte index in
\qnum{wall}{12:35:10}, with observed peak scratch $\qnum{scratchratio}{0.789}n$. Construction
consumes the ordered stream in a single streaming pass without materialising a full suffix array or
an additional text copy; this is not a claim of one physical read of the input. The index contains
$\qnum{chi}{24{,}185{,}339{,}204}$ suffixient witnesses. A rebuilt reader locates $\qnum{limit}{5}$
occurrences in $\qnum{querywall}{0.52}$ s at $\qnum{rss}{547}$ MiB RSS against the approximately
$\qnum{containershort}{63}$ GB container, without materialising its run columns. Independent byte
scanning confirms occurrence counts and resolves an overlapping-match discrepancy with grep. We
report failed optimisations, separate native spool recovery from driver replay, and distinguish
these measurements from an untested full-Pile deployment.
\end{abstract}

\section{Contribution and scope}
The useful question is what it costs to retain exact corpus evidence at a scale where a materialised
suffix array and per-run query columns become impractical. The contribution here is an implemented
construction and reader, with measured resource use and explicit correctness receipts. We claim no
conceptual novelty for suffix indexing, substring statistics, or IDF applied to n-grams. Suffix
arrays, the FM-index and run-length BWT indexing already supply the underlying search operations;
related work is discussed below.

Let $n$ denote input bytes, excluding virtual END. The container's row count includes END, so it is
$n+1$. Decimal GB and TB describe byte sizes; MiB describes binary resident memory. We distinguish
input storage, scratch, final container, and process RSS. The Pile experiment used an existing raw
input file. It did not demonstrate a build from an unseekable input pipe: the sorter uses corpus
access and wave scans. ``Single streaming pass'' describes consumption of the ordered construction
stream, not total corpus I/O. The identity/histogram preparation itself uses a single sequential
pass.\ev{RESUME.md}{``One corpus pass, not
five''}\ev{xsa/runtime/tools/binbwt/scatter_sort.cpp}{comments at lines 1179--1180 and 2526--2527,
per-wave corpus scans}

The evidence is pinned to the repository revision linked in each footnote. Separately committed
studies are pinned to their own revisions. \texttt{paper/NUMBERS.md} maps every quantitative claim
to its source and reproduction command, and explicitly excludes unverified requested figures. These
are historical measurements, not benchmarks rerun for this manuscript.

\section{Method}
\paragraph{Scatter, fused merge, finish.}
The sorter scatters suffix positions into bounded waves, sorts admitted bands and publishes
consumable band files. The merger consumes these files, preserves key order and emits run pieces.
Finish repairs boundary conventions, consumes LCP and endpoint information, sweeps witnesses, and
assembles the container. Producer and finish overlap. A full suffix array is never an intermediate
product: ordered positions exist only in bounded transport bands. A completed band replaces larger
scatter records, and consumption releases storage and
credits.\ev{tools/binbwt/FUSED_TAPE.md}{``Bounded producer/emitter tape''}

Memory limits determine admitted sorting work and staging capacity. They do not imply constant
whole-build RSS independent of corpus size: mapped corpus pages, directories, and witness storage
also contribute. The progress argument requires admitted jobs to finish without another credit,
reserved reorder space for the missing earliest key, and inputs that can be read without waiting on
a future credit-blocked item. The legacy LCP-slice path still has a sorter-to-finish dependency. The
committed design explicitly does not certify the complete pipeline
deadlock-free.\ev{tools/binbwt/DEADLOCK_FREEDOM.md}{``Status'', ``Required architecture'', and
``Bounded-buffer argument''}

\paragraph{Virtual END and LCP in the sorter.}
END is an ordering convention outside the raw byte sequence, not an appended byte chosen because it
happens to be absent. All input bytes remain searchable, and nonempty patterns return corpus offsets
rather than the END position. LCP is produced with sorted bands and consumed as slices by finish; it
need not be reconstructed from a materialised global suffix array. Cross-band state survives band
boundaries. Older finite/cyclic conventions and their checks must not be silently mixed with
virtual-END banks.\ev{REPRODUCE.md}{raw tape input and byte-query
semantics}\ev{tools/binbwt/FUSED_TAPE.md}{optional LCP column and generated-column gates}

\paragraph{What chi stores.}
Following the suffixient-set formulation of Fujimaru et al.~\cite{suffixient}, a suffixient set
selects text positions witnessing occurring right extensions of right-maximal contexts; $\chi$
denotes its cardinality. The sweep maintains active candidates and LCP minima, replacing candidates
until their intervals close. Its bounded active state does not bound the number of witnesses emitted
over the corpus. Member m5 stores a sorted unique position set, not a context-to-rank dictionary.
The bitmap implementation marks witness coordinates in a file-backed bitmap, then scans positions in
order to emit Elias--Fano. This removes a chi-sized heap vector; it does not make bitmap residency
free. Exact count/locate in the lite reader does not consult
m5.\old{222ace4044cdaaf9e3ad8710d954afc5493c12bb}{tools/binbwt/CHI_STUDY.md}{sections ``Structure'',
``Reader inventory'', and ``Why the key universe is not
bounded''}\ev{tools/binbwt/CHI_BITMAP_RESULTS.md}{implementation and completed
measurements}\ev{bit6/SXI_FORMAT.md}{chi set, mmap chi construction, and optional chi}

\paragraph{Bounded decoded-block reader.}
Member m1 is a block-compressed run stream. Sparse row and per-symbol directories navigate to a
block; rank and LF operations decode that block into a bounded cache. The payload is read with
\texttt{pread}; directory mappings use random-access advice and windowed residency drops. This
replaces the old open-time expansion into run heads, lengths and cumulative ranks. The reported
cache arena is $\qnum{arena}{66{,}846{,}720}$ bytes, described in the receipt as approximately
$\qnum{arenashort}{64}$ MB. The approximately $\qnum{rsscap}{550}$ MiB query memory envelope exists
because the reader was rebuilt around this arena and a directory residency policy; it is not an
intrinsic property of compressed indexing or a universal RSS guarantee. The audit field
\texttt{decoded\_bytes=\qnum{decoded}{0}} means no full run-stream materialisation, not that no
blocks were decoded.\ev{tools/binbwt/RESULTS_PILE_100GB.md}{Search certificate, section 1}

\paragraph{Restart safety.}
Durable publication writes and syncs data, atomically publishes it, and syncs its directory before
accepting a receipt. Recovery verifies identity and dependencies. The spool layer follows the
delete-is-commit discipline: discard an input only after durable state and output cover its future
use. The implemented native finish retains raw pieces and LCP dependencies, and publishes immutable
chi bases before deleting older generations. This is a conservative implementation of that
discipline, not eager incremental reclamation.

The container cannot be appended during the sweep. Member counts, directories, offsets and checksums
depend on completed output; the final container is assembled after the sweep. Native recovery
therefore restores spool and machine state and assembles once at EOF. Native finish recovery and
whole-driver recovery are distinct: the native gate keeps sorter and emitter alive; the driver can
replay them and finish.\ev{RESUME_DESIGN.md}{``Implemented finish protocol'', ``What differs'', and
``Cannot be appended finding''}\ev{RESUME.md}{``Journal and publication'' and ``Measured gates:
driver-side resume state''}

\paragraph{Search certificate.}
The command \texttt{query --limit \qnum{limit}{5}} for \verb| function | returns in $\qnum{querywall}{0.52}$ s with $\qnum{rss}{547}$ MiB RSS. Counts after the cache rewrite remain $\qnum{thecount}{704{,}942{,}163}$ for \verb|the |, $\qnum{harper}{55}$ for \verb|Harper Reed|, and $\qnum{functioncount}{4{,}785{,}152}$ for \verb| function |. The certificate uses independent corpus scanning, byte rereads and set comparisons. It verifies $\qnum{sample}{200{,}000}$ located positions for the latter pattern with no bad or duplicate offsets, but does not enumerate the complete answer through the index.\ev{tools/binbwt/RESULTS_PILE_100GB.md}{Search certificate, sections 1--2, ``Positions at scale''}

\paragraph{Recovery and the smaller rungs.}
The killed-and-restarted driver run reports \texttt{avoided\_frac=\qnum{avoided}{0.295695}} and
produces a byte-identical container. This summary combines phase-specific work units; it is not
elapsed-time savings or the fraction of suffix sorting avoided. Remap was reused, while sort, emit
and finish replayed.\ev{RESUME.md}{``150 MB killed mid-sweep, then restarted''} The earlier
$\qnum{ten}{10}$ GB re-bank reports fused finish wall \qnum{tenwall}{31:12} and byte identity with
its bank. Its convention-specific chi value is not interchangeable with subsequent virtual-END
banks.\ev{RESULTS_10G_REBANK.md}{``The run''}

The separate archive-based HPRC rung covers $\qnum{haps}{466}$ haplotypes with
$\qnum{hprcn}{1{,}403{,}221{,}068{,}491}$ indexed symbols and $\qnum{hprcchi}{2{,}250{,}211{,}129}$
witnesses; independent from-zero builds yielded byte-identical containers. This is evidence for a
repetitive genomic workload and an archive route, not a full-Pile tape or search
certificate.\ev{RESEARCH.md}{``THE 466 FROM-ZERO MILESTONE IS DONE'', lines 2460--2469} Earlier HPRC
handoffs expose incompatible corpus joins and parse identities; those are not substitute
oracles.\ev{bit6/H466_LANE_HANDOFF.md}{``Step 1 verdict'' and ``Pairing trap''}

\paragraph{Query applications and serving.}
The query interface exposes maximal exact matches (\texttt{mem}), exact seeds with a target
multiplicity (\texttt{seeds}), rarity-weighted document/region ranking (\texttt{fanout}), and exact
next-byte frequencies (\texttt{branches}). Rarity based on occurrence multiplicity is not
automatically document-frequency IDF. The recorded Cat-article fanout ranks \emph{Cultural
depictions of cats} highest, while also retrieving markup-related pages; this is an inspectable
example, not a relevance benchmark. Its historical materialising reader consumed
$\qnum{catrss}{269}$ GiB at peak and took $\qnum{catwall}{49.03}$ s. Those results must not be
combined with the bounded reader's memory receipt.\ev{SERVING.md}{``Measured: the Cat article on the
100 GB container'', and mem/seeds/fanout sections}

The committed serving table reports $\qnum{ctx}{553.836}$ contexts/s with $\qnum{workers}{32}$
workers, excluding loading and warmup. Later commit messages report a faster branch implementation,
but the requested faster figure lacks a matching committed file receipt and exact measured
invocation in this evidence set; it is excluded. Cold loading is outside warm throughput, and
serving cold-start cost must be measured separately for the bounded
reader.\ev{SERVING.md}{``Reproducible gates'' and ``Measured gates''}

\section{Negative results and oracle failures}
\paragraph{A unique byte is not a minimal sentinel.}
Appending \texttt{\qnum{sentinel}{0xF5}} removed seam classes and preserved the chi count but
changed suffix order at rank $\qnum{rank}{5615}$. Agreement on a scalar statistic did not certify
the order. The older convention required a minimal sentinel, and seam machinery could not be removed
by choosing an absent high byte. Virtual END is an explicit convention change, not a
reinterpretation of this failed experiment.\ev{RESULTS_SENTINEL_NEGATIVE.md}{``Experiments'' and
``What this proves''}

\paragraph{Row coding traded space for time.}
The rowcode study strips a shared band prefix from on-disk rows. A partial large-corpus probe
reduced row bytes by $\qnum{rowcut}{7.9}\%$; the measured smaller-rung sorter wall increased
$\qnum{rowwall}{15.9}\%$. These are different scopes: the former is row encoding in an incomplete
probe, not whole-build peak scratch. The paired $\qnum{ten}{10}$ GB runs reduced sampled total
scratch by $\qnum{scratchcut}{3.48}\%$. The runs overlapped on a shared host, so the wall comparison
is observational. The report's large probe path is Wikipedia, despite its ``pile''
label.\old{e2f1a59b5a0f593c3aeb1c1f8a22d7fb48d82a5e}{tools/binbwt/RESULTS_ROWCODE.md}{T2--T4}

\paragraph{The chi rewrite that measurements retired.}
The chi-on/off A/B attributes approximately $\qnum{chiram}{0.11}n$ RAM and $\qnum{chidisk}{0.13}n$
published disk to chi. Earlier larger memory estimates were sampler artefacts; the measured delta
retired a planned run-stream chi rewrite. This does not make total finish memory equal to chi's
incremental cost.\ev{tools/binbwt/RESULTS_MEMORY_AB.md}{phase table and verdict}

\paragraph{A watchdog was not a progress proof.}
A time cap killed a healthy large run, and its replacement progress watchdog also killed on a
heuristic. Both mechanisms were deleted. Failure propagation, ownership and credit invariants
address correctness; elapsed time without visible activity does not prove
deadlock.\ev{REPRODUCE.md}{build flags, ``There is no --timeout and no --stall-seconds''}

\paragraph{Grep was the wrong occurrence oracle.}
\texttt{grep -o} counts non-overlapping matches. The pattern \verb| function | shares its trailing space with the next occurrence, so grep omitted $\qnum{missed}{192}$ real offsets. Independent scanning and index context queries recover the same missing set, with \texttt{VERIFY n=\qnum{missed}{192} ok=\qnum{missed}{192} bad=\qnum{bad}{0}}. An oracle must match the operation's overlap semantics. The absence of overlapping offsets in grep output cannot establish their absence in the corpus.\ev{tools/binbwt/RESULTS_PILE_100GB.md}{Search certificate, ``The 192-offset discrepancy''}

\section{Related work}
Manber and Myers' suffix arrays provide lexicographic access to suffixes~\cite{sa}. Ferragina and
Manzini's FM-index supplies compressed backward search~\cite{fm}; RLBWT and the r-index exploit BWT
runs for compressed search and locating~\cite{rindex}. This implementation uses that lineage and
makes no claim to originate it or improve its asymptotic bounds.

Yamamoto and Church (\qnum{ycdate}{2001}) explicitly compute term and document frequencies for all
substrings using suffix arrays~\cite{yc}. Thus an implicit inventory of all n-grams and their
frequencies is prior art. Lodhi et al.\ (\qnum{lodhidate}{2002}) develop string kernels over
character subsequences, including comparison with contiguous features~\cite{lodhi}; using
corpus-derived string features is likewise established. IDF is an established term-specificity
weighting, and applying it to n-grams does not create a distinct indexing concept~\cite{idf,yc}. Our
fanout example is evidence of an implemented application, not a claim of a new ranking principle. We
do not provide a matched hardware comparison with these systems and therefore make no
state-of-the-art speed claim.

\section{Limitations and reproduction}
There is no append-into-container operation. Native finish recovery does not establish incremental
whole-driver recovery. There is no search certificate at the true $\qnum{fullpile}{1.31}$ TB Pile
scale. The Pile count and sampled-location certificate does not exhaustively validate all returned
rows for its common pattern. Resource caps on sorting arenas and decoded blocks are not
corpus-independent bounds on total build memory. The observed $\qnum{rsscap}{550}$ MiB query
envelope depends on the rebuilt reader and its residency controls. Cold-start and long LF walks
remain serving costs; the requested cold-first-answer time is unverified in the committed evidence
and is not reported as a measurement.\ev{tools/binbwt/RESULTS_PILE_100GB.md}{``Pile projection'' and
Search certificate limitations}

\texttt{REPRODUCE.md} documents installation, raw-byte input, flags and query gates. The following
commands reproduce the interfaces; the historical headline build receipt does not record its
complete original invocation, so this build command is an explicit reproduction recipe, not a
recovered benchmark command. Use a dedicated scratch directory and a memory budget appropriate to
the host. The input file must already be the desired Pile prefix.
\begin{verbatim}
cd xsa && cargo build --release
cd ..
xsa/target/release/xsa build --tape --input "$CORPUS" \
  --scratch "$SCRATCH" --threads 16 --memory-gb 24 --with-chi
xsa/target/release/xsa query "$CONTAINER" --limit 5 " function "
xsa/target/release/xsa query "$CONTAINER" --count "the " "Harper Reed" " function "
PATH="$PWD/xsa/target/release:$PATH" \
  tools/binbwt/pile_search_certificate.sh \
  "$CONTAINER" "$CORPUS" " function " 200000
\end{verbatim}
The certificate script performs corpus scanning and byte verification in addition to index queries.
Reissue the identical build command with the same scratch directory to test recovery; consult
\texttt{RESUME.md} for fault hooks and \texttt{RESUME\_DESIGN.md} for native-only gates.
\texttt{NUMBERS.md} separates original commands, reconstruction recipes, and unavailable command
provenance. No large build or query experiment was rerun for this paper.
