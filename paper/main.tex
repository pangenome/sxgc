\begin{abstract}
Suffix-array construction here is a radix plan over the distribution of the string, not a
monolithic algorithm. A positional stride sample estimates prefix populations; quantile fences
and a memory-derived row budget determine bands, while a recursive census determines wave split
depth. The radix suffix sort scatters positions into ordered key ranges, sorts full suffixes
locally, and emits BWT runs, LCP, and suffixient witnesses through one ordered-stream pipeline,
without a materialised global suffix array or an additional text copy. The algorithmic property
is adaptation: prefix depth and work-unit size follow the corpus distribution and resource
envelope. Sampling supplies estimates, not worst-case capacity guarantees; position slicing
requires an order proof, and the implementation has finite prefix limits. The Pile evaluation
validates this design on a skewed corpus and reports resource costs, negative results, and
recovery limitations; a full-Pile deployment remains untested.
The local sorting comparison count is $O(n\log B)$ with $B$ bounded by the memory
budget, so for fixed memory $O(n)$, conditional on actual bands meeting that
memory-derived row bound; planning, repeated scans and suffix-symbol inspection are
additional costs.
\end{abstract}

\section{Contribution and scope}
The contribution is the combination of a radix sampling plan and a bounded radix suffix sort.
The plan turns the corpus's prefix distribution into ordered work units; sorting and fused
emission consume those units without a global suffix-order structure. The measured numbers
validate this decomposition rather than define its contribution. Prefix bucketing, suffix
indexing, substring statistics, and IDF applied to n-grams are established ideas. We claim neither
priority for them nor an improved asymptotic suffix-sorting bound.

Let $n$ denote input bytes, excluding virtual END. The container's row count includes END, so it is
$n+1$. Decimal GB and TB describe byte sizes; MiB describes binary resident memory. We distinguish
input storage, scratch, final container, and process RSS. The Pile experiment used an existing raw
input file. It did not demonstrate a build from an unseekable input pipe: the sorter uses corpus
access and wave scans. ``Single streaming pass'' describes consumption of the ordered construction
stream, not total corpus I/O. The identity/histogram preparation itself uses a single sequential
pass.\ev{RESUME.md}{``One corpus pass, not
five''}\ev{xsa/runtime/tools/binbwt/scatter_sort.cpp}{comments at lines 1179--1180 and 2526--2527,
per-wave corpus scans}

\section{Algorithm: plan, radix sort, and fuse}
\label{sec:algorithm}
\subsection{Sampling plan and memory-derived work units}
Write $N=n+1$ for the suffix positions including virtual END. For stride $s$, sample positions
$S=\{0,s,2s,\ldots\}$ in the eligible corpus region. For a prefix class $C$, the census estimates
its population by $\widehat n_C=s\,|S\cap C|$; short tails and END are handled explicitly.
The first-symbol histogram is exact; deeper wave histograms reuse the sample. Sort sampled
prefixes and accumulate their estimated mass in key order. Boundaries at target cumulative
masses are empirical quantiles, rounded to prefix-class boundaries. An oversized class is
refined by its next byte instead of forcing it into a fixed-depth bucket. Thus split depth is
an output of the census, not a corpus-specific tuning parameter.

Let $E$ be the sorter's memory envelope, $F$ its fixed reserve (sample, scan windows,
histograms and control), $G$ its scatter staging, and $\alpha$ a safety fraction. The row arena
is $A=\alpha\max(0,E-F-G)$. If a sorting arm owns $b$ bytes per row and admits $k$ bands
concurrently, the memory-derived target is $R=\lfloor A/(kb)\rfloor$ rows per band.
Here $b$ includes resident row records, permutation/sort workspace, LCP columns and write
staging, not merely the disk record width. The scratch window can shrink $R$ further.
A wave cap $W$ limits staged rows; packing budget-sized bands under this cap determines the
wave count, with $\lceil N/W\rceil$ only an ideal lower bound, not an equality when classes
cannot be packed tightly. Safety slack in both quantile targets reduces estimation risk.
\ev{xsa/runtime/tools/binbwt/scatter_sort.cpp}{\texttt{tape\_budget\_plan},
\texttt{plan\_tape}, and recursive wave descent}

There are two planning levels: wave predicates descend byte by byte, and within-wave band
fences refine prefix windows. Both use population rather than a fixed chosen split depth.
The implementation nevertheless caps predicate width and band-prefix width; arbitrary-depth
recursion is the planning principle, not an unlimited-depth implementation guarantee.

\subsection{Recursion, point masses, and local sorting}
A point mass in the inspected prefix is not necessarily a point mass in full suffix order.
Splitting such a class by position and independently sorting each slice does \emph{not} in
general permit concatenation: equal-prefix suffixes in different slices can interleave.
The implemented fallback therefore proves from the corpus that the entire class is exactly
a maximal single-symbol tail run. In that class, the shorter suffix precedes the longer one
under minimal virtual END, so descending position order is suffix order. Contiguous position
slices can then be emitted highest-first. An unproved class at the prefix-width limit fails
explicitly; it is not silently published. This is the necessary qualification to the claim
that a point mass needs no different sorting algorithm.
\ev{xsa/runtime/tools/binbwt/scatter_sort.cpp}{\texttt{emitPointMass} and
\texttt{SS\_WAVE\_POINT\_MASS\_PROOF}}

For each wave, scan the corpus and scatter positions by the wave predicate and band fences.
Sort each admitted band using full suffix comparisons, resolving equal stored prefixes against
the corpus. Publish completed bands in key order, retaining the preceding suffix across band
boundaries for LCP. The emitter coalesces BWT runs and passes LCP and endpoints to the chi sweep.
This is one consumption of the ordered stream, with boundary state and finish work; it does
not require a second global suffix structure. Neither a global suffix-array file nor an
additional text copy is materialised. The transport's ``merger'' schedules already ordered
ranges; it does not compare overlapping suffix-array fragments to establish their order.

\subsection{Theory: estimation, correctness, work, and memory}
\label{sec:theory}
\paragraph{What the sample guarantees.}
The estimator above is a systematic positional estimator. Uniformly choosing independent
positions would also uniformly sample suffix identities, since each position identifies a
suffix. The actual fixed-stride sample is not that experiment: it is neither independent
random suffix selection nor uniform sampling of lexicographic ranks. Periodicity aligned
with the stride can miss an entire frequent prefix class. Randomising only the starting
offset would not make the observations independent. Consequently no Hoeffding or Chernoff
capacity guarantee is asserted for this implementation. Headroom is heuristic, and even an
unbiased estimator would not alone certify sample-selected quantile boundaries.
Actual scatter counts and admission accounting remain necessary; an underestimated class
can exceed its target. No deterministic bound of $R$ on every band follows from this census.

\paragraph{Local correctness.}
Assume the plan partitions all suffix positions into disjoint, exhaustive intervals in full
suffix order. Prefix fences, ordered by their distinguishing byte with END ordered minimally,
satisfy this invariant; the proved tail slices satisfy it by the position-order argument above.
For bands $B_i$ before $B_j$, every suffix in $B_i$ precedes every suffix in $B_j$.
Sorting full suffixes inside each band and concatenating therefore gives exactly suffix order.
This proof needs no global ranks, prefix doubling, or comparison merge. It does require the
interval invariant: local sorts alone cannot repair arbitrary position partitions. Adjacent
suffix LCP, including the carried boundary pair, and preceding-byte BWT emission then equal
the corresponding global columns. Chi correctness additionally depends on the cited suffixient
sweep and its interval-closing rules; it does not follow from the partition lemma alone.

\paragraph{Resource-parameterised work.}
Let $B\geq 2$ bound the actual rows per band and let $K$ be the band count.
When admission enforces the memory-derived target $R$, take $B=\max(2,R)$.
Then $\sum_i n_i\log(n_i+1)=O(N\log B)$: $O(n\log B)$ with $B$ bounded by the memory
budget, so for fixed memory $O(n)$. The comparison-sort logarithm applies to
$B$, never to $n$; its constant-size factor is set by the resource envelope.
This is not a new asymptotic bound for suffix sorting in general. Adversarial
strings and underestimated populations can produce large bands in the current
implementation. The architectural claim is that the target bound's parameters
come from the resource envelope rather than from $n$, conditional on successful
refinement and admission, not that sampling proves a hard bound.

To state total cost rather than just comparison count, let $m=|S|$, $d$ be the
maximum inspected planning depth, $P$ the number of full corpus scans, $C$ the
corpus-symbol inspections for suffix comparisons and adjacent LCP, and $H$ the
work of wave predicates and band-fence searches. A conservative bound is
\[
 O(md\log(m+1)+Pn+H+K+n\log B+C),
 \qquad H=O(Pnd+Nd\log(K+1)).
\]
Final-container encoding adds its own work. Thus the construction's local sorting
component is linear in $n$ at fixed memory, but total elapsed work is linear only
if these other terms are linear too. In particular, repeated full scans cannot
be absorbed into a constant when the number of waves grows with $n$.

\paragraph{Depth, passes, and I/O.}
Depth is determined by how much key prefix the corpus distribution requires to
separate a class under the row target; it is a separate parameter from input
length, not a prescribed $\log n$ recursion. It need not remain constant as a
corpus grows. Each position is scattered once per wave it belongs to (exactly
one in a disjoint completed plan); each band is sorted once and its output is
streamed once. The implementation nevertheless scans the entire corpus for each
wave, plus preparation and explicit point-mass proofs. If $V_s$ is total scatter
payload bytes and $V_o$ total sorted-band payload bytes, writing and reading each
payload gives sequential volume $O(Pn+V_s+V_o)$, plus final-output bytes.
For disk blocks of $L$ bytes this is $O((Pn+V_s+V_o)/L+K)$ transfers allowing
partial band blocks. Corpus probes add cache misses, conservatively at most
$O(C+H)$ further transfers.

\paragraph{Cache coherence and its boundary.}
The bulk data path streams the corpus forward, appends band payloads through a
bounded number of sequential output streams, sorts each admitted band in RAM,
and emits in key order. Its ordering state is bucket-local: no global pointer
chasing, tree walk, or random access over an $n$-row suffix-order structure is
required. This locality is a first-class systems advantage of choosing bands
from the cache and memory envelope. The text need not be wholly resident and
has no additional materialised copy; the existing corpus is file-backed.
This does not mean every text access is sequential: full suffix comparisons and
LCP computation can probe distant mapped corpus pages, whose residency and
misses remain real costs. In comparison-based suffix sorting a comparison may
walk a long common prefix, so its effective cost is an LCP-length scan, not a
unit-cost compare; banding confines row workspace but does not eliminate this
cost. Usual monolithic RAM forms of SA-IS, DC3 and prefix doubling maintain
whole-text arrays occupying multiples of $n$ bytes~\cite{sais,dc3,sa}.
At the measured $n=\qnum{input}{10^{11}}$ bytes, such workspace can exceed a fixed
machine budget even when the input fits on disk. This is a capacity argument,
not a measured failure of those competing implementations.

\paragraph{Point masses and the Pile evidence.}
Long common prefixes still make sorting within a band expensive. A point mass
at the inspected prefix therefore calls for deeper refinement, not simply a
larger band; if deeper keys cannot split it, a proved analytic case or an
explicit failure is required. The Pile case at $\qnum{input}{10^{11}}$ bytes
illustrates the pressure: the source records that the space class and its
largest byte pair exceed wave capacity, requiring deeper waves than the shallow
encyclopedic-text rule. The diagnostic recording this shape is
\texttt{SS\_WAVE\_DEPTH depth\_hist=...}, emitted in
\texttt{xsa/runtime/tools/binbwt/scatter\_sort.cpp}.
\ev{xsa/runtime/tools/binbwt/scatter_sort.cpp}{wave-list rationale at lines
1160--1171 and depth diagnostic at lines 2524--2527}
The headline receipt quantifies the completed build as
$\qnum{waves}{102}$ waves; it does not provide a numeric depth histogram.
\ev{tools/binbwt/RESULTS_PILE_100GB.md}{opening build receipt}
We therefore attribute the whitespace-depth explanation to the source and do
not turn the diagnostic format into an invented measured depth.

\paragraph{Memory model and its boundary.}
For actual admitted rows $a_i$, owned sorting memory is $F+G+b\sum_i a_i$; admission aims
to keep $b\sum_i a_i\leq A$. At fixed envelope, concurrency and sample cap, this arena term
has no $n$ multiplier. It explains how sorting-owned anonymous memory can remain bounded
as the corpus grows, rather than asserting constant whole-build peak anonymous memory or RSS.
The current row gate admits a band larger than the entire cap alone and reports its peak;
therefore a badly underestimated or width-limited band can violate the nominal arena bound.
A universal bound would require exact refinement or an external spill fallback before that
admission. File-backed corpus pages, plan metadata, directories and witness storage are
separate terms. Peak RSS is consequently not proved independent of $n$.

and oversize-band admission}

\section{Fused construction and supporting implementation}

\paragraph{Scatter, fused merge, finish.}
The sorter scatters suffix positions into bounded waves, sorts admitted bands and publishes
consumable band files. The merger consumes these files, preserves key order and emits run pieces.
Finish repairs boundary conventions, consumes LCP and endpoint information, sweeps witnesses, and
assembles the container. Producer and finish overlap. A full suffix array is never an intermediate
product: ordered positions exist only in bounded transport bands. A completed band replaces larger
scatter records, and consumption releases storage and
credits.\ev{tools/binbwt/FUSED_TAPE.md}{``Bounded producer/emitter tape''}

Memory limits determine admitted sorting work and staging capacity. They do not imply constant
whole-build RSS independent of corpus size: mapped corpus pages, directories, and witness storage
also contribute. The progress argument requires admitted jobs to finish without another credit,
reserved reorder space for the missing earliest key, and inputs that can be read without waiting on
a future credit-blocked item. The legacy LCP-slice path still has a sorter-to-finish dependency. The
committed design explicitly does not certify the complete pipeline
deadlock-free.\ev{tools/binbwt/DEADLOCK_FREEDOM.md}{``Status'', ``Required architecture'', and
``Bounded-buffer argument''}

\paragraph{Virtual END and LCP in the sorter.}
END is an ordering convention outside the raw byte sequence, not an appended byte chosen because it
happens to be absent. All input bytes remain searchable, and nonempty patterns return corpus offsets
rather than the END position. LCP is produced with sorted bands and consumed as slices by finish; it
need not be reconstructed from a materialised global suffix array. Cross-band state survives band
boundaries. Older finite/cyclic conventions and their checks must not be silently mixed with
virtual-END banks.\ev{REPRODUCE.md}{raw tape input and byte-query
semantics}\ev{tools/binbwt/FUSED_TAPE.md}{optional LCP column and generated-column gates}

\paragraph{What chi stores.}
Following the suffixient-set formulation of Fujimaru et al.~\cite{suffixient}, a suffixient set
selects text positions witnessing occurring right extensions of right-maximal contexts; $\chi$
denotes its cardinality. The sweep maintains active candidates and LCP minima, replacing candidates
until their intervals close. Its bounded active state does not bound the number of witnesses emitted
over the corpus. Member m5 stores a sorted unique position set, not a context-to-rank dictionary.
The bitmap implementation marks witness coordinates in a file-backed bitmap, then scans positions in
order to emit Elias--Fano. This removes a chi-sized heap vector; it does not make bitmap residency
free. Exact count/locate in the lite reader does not consult
m5.\old{222ace4044cdaaf9e3ad8710d954afc5493c12bb}{tools/binbwt/CHI_STUDY.md}{sections ``Structure'',
``Reader inventory'', and ``Why the key universe is not
bounded''}\ev{tools/binbwt/CHI_BITMAP_RESULTS.md}{implementation and completed
measurements}\ev{bit6/SXI_FORMAT.md}{chi set, mmap chi construction, and optional chi}

\paragraph{Bounded decoded-block reader.}
Member m1 is a block-compressed run stream. Sparse row and per-symbol directories navigate to a
block; rank and LF operations decode that block into a bounded cache. The payload is read with
\texttt{pread}; directory mappings use random-access advice and windowed residency drops. This
replaces the old open-time expansion into run heads, lengths and cumulative ranks. The reported
cache arena is $\qnum{arena}{66{,}846{,}720}$ bytes, described in the receipt as approximately
$\qnum{arenashort}{64}$ MB. The approximately $\qnum{rsscap}{550}$ MiB query memory envelope exists
because the reader was rebuilt around this arena and a directory residency policy; it is not an
intrinsic property of compressed indexing or a universal RSS guarantee. The audit field
\texttt{decoded\_bytes=\qnum{decoded}{0}} means no full run-stream materialisation, not that no
blocks were decoded.\ev{tools/binbwt/RESULTS_PILE_100GB.md}{Search certificate, section 1}

\paragraph{Restart safety.}
Durable publication writes and syncs data, atomically publishes it, and syncs its directory before
accepting a receipt. Recovery verifies identity and dependencies. The spool layer follows the
delete-is-commit discipline: discard an input only after durable state and output cover its future
use. The implemented native finish retains raw pieces and LCP dependencies, and publishes immutable
chi bases before deleting older generations. This is a conservative implementation of that
discipline, not eager incremental reclamation.

The container cannot be appended during the sweep. Member counts, directories, offsets and checksums
depend on completed output; the final container is assembled after the sweep. Native recovery
therefore restores spool and machine state and assembles once at EOF. Native finish recovery and
whole-driver recovery are distinct: the native gate keeps sorter and emitter alive; the driver can
replay them and finish.\ev{RESUME_DESIGN.md}{``Implemented finish protocol'', ``What differs'', and
``Cannot be appended finding''}\ev{RESUME.md}{``Journal and publication'' and ``Measured gates:
driver-side resume state''}

\subsection{Negative results and oracle failures}
\paragraph{A unique byte is not a minimal sentinel.}
Appending \texttt{\qnum{sentinel}{0xF5}} removed seam classes and preserved the chi count but
changed suffix order at rank $\qnum{rank}{5615}$. Agreement on a scalar statistic did not certify
the order. The older convention required a minimal sentinel, and seam machinery could not be removed
by choosing an absent high byte. Virtual END is an explicit convention change, not a
reinterpretation of this failed experiment.\ev{RESULTS_SENTINEL_NEGATIVE.md}{``Experiments'' and
``What this proves''}

\paragraph{Row coding traded space for time.}
The rowcode study strips a shared band prefix from on-disk rows. A partial large-corpus probe
reduced row bytes by $\qnum{rowcut}{7.9}\%$; the measured smaller-rung sorter wall increased
$\qnum{rowwall}{15.9}\%$. These are different scopes: the former is row encoding in an incomplete
probe, not whole-build peak scratch. The paired $\qnum{ten}{10}$ GB runs reduced sampled total
scratch by $\qnum{scratchcut}{3.48}\%$. The runs overlapped on a shared host, so the wall comparison
is observational. The report's large probe path is Wikipedia, despite its ``pile''
label.\old{e2f1a59b5a0f593c3aeb1c1f8a22d7fb48d82a5e}{tools/binbwt/RESULTS_ROWCODE.md}{T2--T4}

\paragraph{The chi rewrite that measurements retired.}
The chi-on/off A/B attributes approximately $\qnum{chiram}{0.11}n$ RAM and $\qnum{chidisk}{0.13}n$
published disk to chi. Earlier larger memory estimates were sampler artefacts; the measured delta
retired a planned run-stream chi rewrite. This does not make total finish memory equal to chi's
incremental cost.\ev{tools/binbwt/RESULTS_MEMORY_AB.md}{phase table and verdict}

\paragraph{A watchdog was not a progress proof.}
A time cap killed a healthy large run, and its replacement progress watchdog also killed on a
heuristic. Both mechanisms were deleted. Failure propagation, ownership and credit invariants
address correctness; elapsed time without visible activity does not prove
deadlock.\ev{REPRODUCE.md}{build flags, ``There is no --timeout and no --stall-seconds''}

\paragraph{Grep was the wrong occurrence oracle.}
\texttt{grep -o} counts non-overlapping matches. The pattern \verb| function | shares its trailing space with the next occurrence, so grep omitted $\qnum{missed}{192}$ real offsets. Independent scanning and index context queries recover the same missing set, with \texttt{VERIFY n=\qnum{missed}{192} ok=\qnum{missed}{192} bad=\qnum{bad}{0}}. An oracle must match the operation's overlap semantics. The absence of overlapping offsets in grep output cannot establish their absence in the corpus.\ev{tools/binbwt/RESULTS_PILE_100GB.md}{Search certificate, ``The 192-offset discrepancy''}

\section{Algorithmic comparison and prior art}
SA-IS reduces to LMS substrings and induces the remaining order; DC3 recursively ranks a
difference-cover sample and merges the remaining suffixes~\cite{sais,dc3}. Their usual RAM
forms coordinate whole-text suffix-order arrays, with linear work and linear space. This
contrasts with independent key intervals here, but does not imply that induced sorting or DC3
cannot be adapted to external memory. Prefix doubling instead repeatedly sorts pairs of
ranks for growing prefix lengths and updates ranks across the text~\cite{sa}; our local
comparisons resolve suffixes without those global rank rounds.

External and distributed suffix construction already use partitioning, sorting and merging;
prefix bucketing itself is not the contribution. External induced sorting and distributed
prefix-doubling/DC variants also show why ``external'' is not a single competing algorithm
\cite{bingmann}. eGSA, for example, builds local enhanced suffix arrays and merges them,
including BWT and LCP information~\cite{egsa}. LCP co-construction therefore is also prior art.
The distinction claimed here is the concrete combination of sampled-census adaptive prefix
depth, work units derived from a memory envelope, and fused BWT/chi/LCP ordered-stream
consumption without a persisted global suffix array. Ordered prefix intervals remove the
comparison merge required for overlapping local arrays. These are architectural differences,
not a priority claim for each ingredient or an asymptotic improvement over those algorithms.

Manber and Myers' suffix arrays provide lexicographic access to suffixes~\cite{sa}. Ferragina and
Manzini's FM-index supplies compressed backward search~\cite{fm}; RLBWT and the r-index exploit BWT
runs for compressed search and locating~\cite{rindex}. This implementation uses that lineage and
makes no claim to originate it or improve its asymptotic bounds.

Yamamoto and Church (\qnum{ycdate}{2001}) explicitly compute term and document frequencies for all
substrings using suffix arrays~\cite{yc}. Thus an implicit inventory of all n-grams and their
frequencies is prior art. Lodhi et al.\ (\qnum{lodhidate}{2002}) develop string kernels over
character subsequences, including comparison with contiguous features~\cite{lodhi}; using
corpus-derived string features is likewise established. IDF is an established term-specificity
weighting, and applying it to n-grams does not create a distinct indexing concept~\cite{idf,yc}. Our
fanout example is evidence of an implemented application, not a claim of a new ranking principle. We
do not provide a matched hardware comparison with these systems and therefore make no
state-of-the-art speed claim.

\section{Limitations and reproduction}
There is no append-into-container operation. Native finish recovery does not establish incremental
whole-driver recovery. There is no search certificate at the true $\qnum{fullpile}{1.31}$ TB Pile
scale. The Pile count and sampled-location certificate does not exhaustively validate all returned
rows for its common pattern. Resource caps on sorting arenas and decoded blocks are not
corpus-independent bounds on total build memory. The observed $\qnum{rsscap}{550}$ MiB query
envelope depends on the rebuilt reader and its residency controls. Cold-start and long LF walks
remain serving costs; the requested cold-first-answer time is unverified in the committed evidence
and is not reported as a measurement.\ev{tools/binbwt/RESULTS_PILE_100GB.md}{``Pile projection'' and
Search certificate limitations}

\texttt{REPRODUCE.md} documents installation, raw-byte input, flags and query gates. The following
commands reproduce the interfaces; the historical headline build receipt does not record its
complete original invocation, so this build command is an explicit reproduction recipe, not a
recovered benchmark command. Use a dedicated scratch directory and a memory budget appropriate to
the host. The input file must already be the desired Pile prefix.
\begin{verbatim}
cd xsa && cargo build --release
cd ..
xsa/target/release/xsa build --tape --input "$CORPUS" \
  --scratch "$SCRATCH" --threads 16 --memory-gb 24 --with-chi
xsa/target/release/xsa query "$CONTAINER" --limit 5 " function "
xsa/target/release/xsa query "$CONTAINER" --count "the " "Harper Reed" " function "
PATH="$PWD/xsa/target/release:$PATH" \
  tools/binbwt/pile_search_certificate.sh \
  "$CONTAINER" "$CORPUS" " function " 200000
\end{verbatim}
The certificate script performs corpus scanning and byte verification in addition to index queries.
Reissue the identical build command with the same scratch directory to test recovery; consult
\texttt{RESUME.md} for fault hooks and \texttt{RESUME\_DESIGN.md} for native-only gates.
\texttt{NUMBERS.md} separates original commands, reconstruction recipes, and unavailable command
provenance. No large build or query experiment was rerun for this paper.
