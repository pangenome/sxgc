# Disjoint PFP ranges, ordered block publication

Status: opt-in resident **row emitter**, not a new sort, membership rule, parallel witness sweep or product format. Leave live serial builds alone. `XSA_RESIDENT_RADIX_LANES=1` is the serial control (default). 2–8 enables scoped worker threads. The step is in sorted **dictionary SA ranks**, not fixed prefix depth, text offsets, or estimated output bytes. Default 16,384, at least 2,048 except in small fixtures. No extra byte-level SA/LCP or triples file.

* A dictionary rank may be non-owned. Equal **finite** owned tails must stay together: their rows interleave by successor parse rank, not dictionary word or source offset. In parallel, inspect each raw interval for its first and last owned tail and its first different tail if needed. Join this small fence table, omitting empty intervals. If the first tail equals the previous nonempty interval's last tail, move the cut to the next distinct tail **in this interval**, or absorb it completely. Never chase the same long group through many subsequent raw intervals. Preserve the preceding owned key at every retained cut. This avoids a serial full-dictionary classification pass. Edge probes can still cost linear RAM traffic in the worst case; record `plan_s`.
* Each worker scans disjoint ranges in the shared, read-only ordered dictionary. It computes the **first** LCP against the preceding range's finite tail; internal ties use the unchanged continuation-rank heap/aligned LCP rule. One global END precedes all ranges. Encode complete final 12-byte rows in the worker, including the row43 highs where applicable. Partition correctness is about the **global adjacent row**, not just local sortedness.
* Many small ranges are distributed round-robin, not one huge range per thread. Each lane has two reusable 65,536-row blocks and private credits; no worker can fill another's queue. A frequent phrase can generate more rows than fit a tile buffer: stream as many blocks as needed without accumulating the tile. The ordered consumer forwards those bytes (and tees the identical bytes to the verifier if enabled). No per-row decoding, key comparisons, heap merge, or LCP patch at the join. Backpressure on the actual consumers remains; a single huge equal group still has one owner. Observe max tile mass, per-lane row totals and ordered wait rather than assuming perfect balance.
* Before planning, reserve O(ceil(D/step)) fence/cut arrays, thread stacks, and `lanes * 2 * 65,536 * 12` row bytes. Before emission, bound the **sum of individual lane heap high-water capacities** using lane maximum rank extent and k, allowing for a moving realloc; refuse if this exceeds the reserved pool. Count row queues against live scratch as well as RAM when gating. Files are not used for reordering. On volatile-state loss, replay.

`bash gates/overlap_radix_stage.sh`: private cold 100 MB prepared refs/IDs/corpus, 2 GiB shared producer/hash quota, four CPU quota, ~1.4 GiB arrays, no swap. Certify a reference row-stream SHA with an independent cold raw verifier (140 MiB/1 CPU), then time streaming **to the hash sink** with serial / four / two / repeat-serial, same executable, grants and checksums. Compare emit and total wall separately, check descriptor/group/row counts and output SHA. Not raw-to-product, not a full SHA-certified container, and not a speed claim for 10 GB. Run bounded producer fixtures with tiny cuts through equal, omitted and EOF keys, both resident widths and row43, before larger arms. Product promotion needs its own full test incl. finish, raw verifier, cold inputs, scratch and shared IO; no Pile launch from a microbenchmark.

**Next serial cost to test: slice writes.** In the matched 3 GB bitmap arm the product sink performed 97,806,589 write-family calls despite only 2.76 MB attributed storage writes. The finish counted 48,756,731 LCP escape entries visited (consumer loads can overlap). The slice encoder writes *two separate 8-byte fields per escape*. This predicts tens of millions of avoidable syscalls even on tmpfs; it does not mean the job is disk-bandwidth-bound. `XSA_BATCH_SXLS_ESCAPES=1` writes the same flat little-endian `(rank, LCP)` pairs together in one write per nonempty slice, with the same marker bytes, header, sync/rename/credit semantics and bounded working set. Default remains scalar so the full radix A/B doesn't change two variables. `bash gates/overlap_sxls_pair.sh` feeds the **certified 100 MB row stream**, makes both publications for *each* actual slice in alternating order, checks every byte/escape and immediately retires both. Both copies use fresh private counted tmpfs; no full SA/LCP, no fake measured seek counts. Prediction: at least 99% of `2*escapes - nonempty_slices` write calls disappear. Time only encode/write/sync/publication for the two arms; real downstream backpressure and full-product wall require a separate test. This local trial does not turn the state-dependent witness sweep into a concatenation.

**Slice writer PASS** (`1d1843b`, `sxls-pair-100m-LZJusF`, [result](gates/receipts/sxls-pair-100m/result.json)). The same 100,000,504 certified production rows yielded 382 slices with 1,129,147 escapes. All headers, markers, escape pairs and done markers matched; independent decoding checked every original byte LCP. Same 192 MiB/1 CPU writer, no swap: write-family calls **2,259,058 → 1,146**, exactly 2,257,912 fewer, as predicted. Local encode/write/sync/publish **2.306 → 0.208 s (11.06×)**. Zero attributed disk bytes in either measured publication path: this is syscall/CPU overhead on tmpfs, *not* a disk write saving. Both copies together peaked at 4,821,472 logical bytes; with producer/queues the conservative counted bound was 53,858,756 B / 200,001,006 B. About 2.10 s of slice work saved at this size, not an 11× build. Leave the matched emitter A/B unchanged; enable batching in a separately labeled full arm if timing the product effect.

**Full A/B:** `bash gates/overlap_radix_product.sh` runs two fresh packed-raw 1 GB builds, both with volatile bitmap and pieces, same executables, 20 GiB / 4 CPU build and separate 1,400 MiB / 1 CPU verifier. It refuses to overlap a running 10 GB control. Select the best small-study lane count (prefer 2 if within 10% of 4). Each arm must match all external ranks, every independently checked row, the same nine-member container SHA, grants, and ≤2N scratch. In the parallel arm count the entire reserved row FIFO against both arrays and live scratch even before the packed tape is retired. Report raw, prepared, emit and blocked-write time separately. For a full-product speed win require emit ≤0.90×, raw wall ≤0.95× and post-front worker reads/writes ≤1.05× serial. If the downstream sink/finish/verifier wins the race to become the bottleneck, keep the emitter-stage result separate and do not claim a product speedup.
