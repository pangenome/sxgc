# Disjoint PFP ranges, ordered block publication

Status: opt-in resident **row emitter**, not a new sort, membership rule, parallel witness sweep or product format. Leave live serial builds alone. `XSA_RESIDENT_RADIX_LANES=1` is the serial control (default). 2–8 enables scoped worker threads. The step is in sorted **dictionary SA ranks**, not fixed prefix depth, text offsets, or estimated output bytes. Default 16,384, at least 2,048 except in small fixtures. No extra byte-level SA/LCP or triples file.

* A dictionary rank may be non-owned. Equal **finite** owned tails must stay together: their rows interleave by successor parse rank, not dictionary word or source offset. In parallel, inspect each raw interval for its first and last owned tail and its first different tail if needed. Join this small fence table, omitting empty intervals. If the first tail equals the previous nonempty interval's last tail, move the cut to the next distinct tail **in this interval**, or absorb it completely. Never chase the same long group through many subsequent raw intervals. Preserve the preceding owned key at every retained cut. This avoids a serial full-dictionary classification pass. Edge probes can still cost linear RAM traffic in the worst case; record `plan_s`.
* Each worker scans disjoint ranges in the shared, read-only ordered dictionary. It computes the **first** LCP against the preceding range's finite tail; internal ties use the unchanged continuation-rank heap/aligned LCP rule. One global END precedes all ranges. Encode complete final 12-byte rows in the worker, including the row43 highs where applicable. Partition correctness is about the **global adjacent row**, not just local sortedness.
* Many small ranges are distributed round-robin, not one huge range per thread. Each lane has two reusable 65,536-row blocks and private credits; no worker can fill another's queue. A frequent phrase can generate more rows than fit a tile buffer: stream as many blocks as needed without accumulating the tile. The ordered consumer forwards those bytes (and tees the identical bytes to the verifier if enabled). No per-row decoding, key comparisons, heap merge, or LCP patch at the join. Backpressure on the actual consumers remains; a single huge equal group still has one owner. Observe max tile mass, per-lane row totals and ordered wait rather than assuming perfect balance.
* Before planning, reserve O(ceil(D/step)) fence/cut arrays, thread stacks, and `lanes * 2 * 65,536 * 12` row bytes. Before emission, bound the **sum of individual lane heap high-water capacities** using lane maximum rank extent and k, allowing for a moving realloc; refuse if this exceeds the reserved pool. Count row queues against live scratch as well as RAM when gating. Files are not used for reordering. On volatile-state loss, replay.

Certify a reference row-stream SHA with an independent cold raw verifier (140 MiB/1 CPU), then time streaming **to the hash sink** with serial / four / two / repeat-serial, same executable, grants and checksums. Compare emit and total wall separately, check descriptor/group/row counts and output SHA. Not raw-to-product, not a full SHA-certified container, and not a speed claim for 10 GB. Run bounded producer fixtures with tiny cuts through equal, omitted and EOF keys, both resident widths and row43, before larger arms. Product promotion needs its own full test incl. finish, raw verifier, cold inputs, scratch and shared IO; no Pile launch from a microbenchmark.
