## A concrete fit route to try, not implemented or admitted

Use the actual 100 GB scan `m=3,181,334,488`, maximum owned stride 201,606. Keep every public key, ordinal, rank, LCP and address 64-bit. Two byte-accurate design changes target different constraints:

1. **Resident parallel front under the illustrative 140 GiB array comparison.** Today's front charges **176,364,610,632 B**. Store one `u64` ordinal per sortable row instead of `(cached prefix, ordinal)`. Read the prefix/full lexical comparison from resident raw at `start[ord]`. Represent starts in blocks of 16,384: `u64 base` + checked relative displacement, wide fallback on any exceptional block (reserve/check before use, never truncate). On this scan the largest possible in-block difference is `16383*201606 = 3,302,911,098 < 2^32`; **that**, not text size, justifies 4-byte displacements even above a 4 GiB raw offset. After sorting, save one distinct-head bit per sorted slot; per-bin independent word padding fits the control margin. Compute relative and absolute dictionary ranges with exact comparisons, write each bin in place. Release the raw mapping before allocating the final 8m key buffer. Now walk immutable ordinals, head bits and stride starts: on each new head the address advances by its header and the preceding word's exact raw length (`owned+8` except EOF); scatter current address to `keys[ord]`. This doesn't need a second tape read or a rank spool.

   Proposed first-phase upper `N+4(m+1)+8ceil((m+1)/16384)+8m+8ceil(m/64)+12 MiB` = **138,587,816,980 B (129.07 GiB)** at four workers, leaving 11,736,038,380 B against 140 GiB *arrays*, not a shared-service admission. Post-raw phase upper with the 8m key buffer = **64,038,492,884 B**. Keep concurrent output cache, runtime, metadata and cold barriers in the service budget. Removing the cached prefix may substantially hurt comparisons; record bin skew, phase wall, process CPU, IO and verifier identity before any adoption. This is a layout option for the real front, not another unconnected codec benchmark.

2. **Bound the rank handoff even when `k,U` are not yet known.** The current native triple `T + 16m` (`T=U+16k-8`) can reach **201,802,703,608 B** before margin. If actually too large, during certified parse ordering persist the bit for each first head in rank order, with 64-bit prefix counts per 512 slots; persist a tape address every 64 distinct records. `inverse[j]` yields slot `r-1`, popcount rank yields head ordinal, sample plus ≤63 complete record skips yields the canonical `u64` address. Successor ties and numeric key ordering are unchanged. Compute the text-order key SHA **before** retirement. Fsync/pin the compact map first, close/unmap every reference to the private generated keys, and retire **only that inode**, before creating the inverse file. A process holding an unlinked mapping still owns blocks. Restart a failed unpublished handoff from raw; don't delete a banked input.

   With `k<=m`, samples + bits + counts ≤ `8ceil(k/64)+8ceil(m/64)+8ceil(m/512)` = **845,041,984 B** worst case. `T + 8m + navigation + 4 MiB` ≤ **177,201,263,992 / 200,000,000,000 B** for this phase (either keys or inverse present, not both). That's a conditional file ledger for a *different* handoff, not today's gate. Verify the reconstructed key sequence against the independently raw-authenticated source digest and independently check all inverse ranks and successor recurrences. Verifying a map against ranks used to derive that same map without an independent key/text witness is circular. Measure the extra pointer chasing; if actual `T+16m+margin` fits, direct columns may be preferable.

Neither change by itself solves the emitting workspace. The dense reference consumer's worst-case 259.80 GiB includes the lexical tape, navigation and PLCP but **no finite-tail ordering arena, sink, oracle or v10 trie**. The next proposal needs measured `k,U`, distinct suffix-group skew and phase liveness, compressed or bounded-access word/occurrence navigation, complete range seam and tie tests, and canonical ten-member identity. Keep large-scale estimates separate from the completed v8 products and the real prepared-rank result.
