# Same folds, different LCP slice files: price the 400-credit alternative

The [m12-only study](../gates/receipts/v10-target-credits/) rejects the 100 MB five-slice window at the target. Rather than changing run pieces or the finish, consider a **new** seam-free row handoff with the same 65,536 maximal runs per piece, the same 262,144 rows per SXLS, but 400 slice credits. No production switch or allocation. Disk credits and retained reader memory are different quantities. First require every archived PRC1 cut in the pinned journal (run ordinals, row span, shard and serialized size) to agree with the m12 super-samples, each finish release to agree with an advancing durable m1 sync, and same two-run lag / complete terminal drain in the pinned finish: 478,846 pieces, 478,847 loads, `n + pieces` staged rows, no seams, no m14. This is evidence about the historical construction; the canonical raw LCP stream still has to be verified independently in any *new* build. The old spool inventory is not a new spool or an exemption from scratch.

[First extraction refused](../gates/receipts/v10-fold-cut-order-stop/): journal durable records 79 and 78 occur in that order. Check the complete ordinal permutation against m12 with a 59,856-byte bitset; journal line order is not suffix or consumer-release order. The independent ordered release/sync checks remain mandatory.

**Transfer invariant.** For a fixed fold covering interval `I` of `L` rows (including the preceding rank), let `W(A)=|A| + 16×escapes(A)`. A nonempty slice has exactly one marker per row and at most one 16-byte pair per row. The historical reader diagnostic `H_old` majorizes `L + W(I)` on every job, since its copied source slices covered `I`. Repartitioning *the same rows* into regular slices of size `S` can add at most `S−1` rows on each side of `I`. Therefore `H_new ≤ H_old + 34×(S−1)`. Take the smaller of this upper and the prior m12 geometric upper. An old reported high need not be the new high. Changing the actual **run-piece** cuts, coalescing, or LCP stream invalidates this transfer even if totals agree. Also `H_old ≥ 2L + 16e ≥ 18e` for the staged deep pair count `e`. Conditional on the audited fresh-band/single-job libstdc++ growth policy, charge old + new power-of-two deep vectors during growth; the alternative transient 16S-byte raw escape input buffer is earlier, not simultaneous. See the [source-loader analysis](overlap_finish_fold.md). This is not a process or joint RSS cap; data arrays, worker jobs, trie, cache and allocator still need separate qualification.

**Scratch and traffic.** Price **all** 400 full SXLS (worst case all escapes), 78 width-37 PRC1 payloads, all BPG1 logical progress extents, full inverse and half-N posting, separate 4 MiB producer margin, actual historical spacing-22 PFCK, bitmap, m11 sparse tails, expected m20 and a generic m5 EF upper. Conservatively add EF even while charging both pools. Keep lifetime allocation distinct from total serialized bytes. The subtotal omits e.g. directory/inode/block-rounding, physical over-allocation, transport and revised control/log bounds; it is **not 100 GB fit**. Can the same monitored filesystem semantics even scale to >1M names? The 4096-inode fixture cannot. Rank/position/base are 37 bit, PRC1 **lengths** bounded by largest full piece span, proposed per-slice storage may use checked u32 only for a run with a verified LCP bound; the 100 MB u16 implementation is not applicable just because each 100 GB escape still fits u64 on wire.

**Independent verification cost.** Conditional on the reported exact max LCP `M` and `E` escaped adjacent LCPs, bound actual equal-prefix bytes demanded by the current memcmp-per-edge checker, not wall, page faults or device IO. At depth `d`, count of adjacent LCPs ≥d = number of length-d substrings **with multiplicity** minus number of distinct values. An equal pair of length `M` supplies `M−d+1` different later start positions with earlier duplicates, even for overlapping occurrences. For `d≤255`, at least `E` adjacent LCPs also reach that depth. Sum the **max**, not the sum, of the lower bounds at each depth. Upper `254×(n−E) + M×E` when there are escapes (`n` includes END). The native checker inspects two strings and also checks order, predecessors and final rank; this is a lower bound on prefix *lengths*, not a lower bound on two separate physical reads per byte. No time from bytes divided by an assumed SSD speed.

One CPU/128 MiB/no swap, ≤120 s, no eviction or raw input.
