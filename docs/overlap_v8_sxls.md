# Checked SXLS writer for the fixed v8 handoff

**A sink component, not a joint launch.** `XSA_TEST_V8_100M_SXLS_SLOTS=1` additionally requires the [fixed PRC1 pool's exact guarded profile](overlap_v8_piece_pool.md) and the 2N scratch gate. No other sink changes its slice layout or buffer sizes. Only a private narrow pipe (≤512 KiB) is accepted. As before, the supervisor must authenticate inputs and use the independent [raw row fence](overlap_finish_credits.md): suffix order is **not** proved by this writer. Failure may leave a prefix of real files.

The published SXLS v1 file still starts with 48 B, then one byte per rank, then 16 B per escape (u64 LE rank and exact LCP). The maximum in its header is the maximum **escaped** value, or zero if none. The old writer holds a `Vec<u64>` slice, byte markers and a growing escape column concurrently. On the historical largest full slice (134,284 escapes) those live elements alone occupy **4,507,840 B**, before spare capacity or input buffering. This is not an RSS measurement.

The new writer checks against 34,067 **before** narrowing to u16. It holds exactly one 262,144-element slice plus a shared 65,536-byte output page: **589,824 B** of codec arrays, independent of escape density. Count escape tuples and check `48 + rows + 16*escapes` as each LCP arrives. At publication copy capped markers through the page, then scan the same values for LE escape pairs through the same page. Including the 8,192-row narrow input packet gives **688,128 B** of these named arrays. This does not include the cutter, allocator, stack, mapped raw, kernel pipe, finish or page cache; it is not a limit on the whole service. No write/syscall/time improvement asserted.

Five private slot inodes use the same bounded non-seeking writer, extent/identity checks and no-replace hard link as PRC1, in `bands/slice-slots/` with **separate** SXLS names. A linked old slot refuses **before truncate**. Check the old empty `.done` and `.consumed` and absence of the old canonical payload when recycling. The non-spooling frozen finish closes its reader and unlinks the payload before returning credit; it may **still retain a RAM copy**. Only create the new `.lcp.done` after the complete fsynced slot is linked under `band_i.lcp`. Keep the last image until input EOF and final row/escape/peak checks; remove private names and close writer FDs before `cutter.finish()` publishes BPT1. Canonical names still needed by the finish remain intact. The same private-namespace/no-stale-reader stipulation as PRC1 applies; old FDs are not immutable snapshots across reuse.

Charge all five slots through the sweep: **12,053,680 B** even if some are currently inactive. Together with the 78 PRC1 slots, **72,120,856 B** of logical payload capacity (not including markers, controls, allocated blocks, final output or any finish files). This enforces two terms *already in* the 119,835,911 B candidate model, **not** extra space saved against it. The legacy `scratch_gate` samples are explicitly partial; they are not proof of that joint envelope.

[Fixture results](../gates/receipts/v8-sxls-slots-fixtures/): 9 wire cases incl no escapes, 255-marker/4,096-tuple and 65,536-byte page cuts, and the maximum 2,410,736-byte image. The actual legacy batch serializer and an independent wire oracle both matched across cyclic reuse, exact and short tails. Extra links, early/malformed credits, stale markers, too-large values/extents, incomplete input and STOP while stalled were refused. One synthetic truncated pipe left exactly **262,192 B** under two names on **one** inode, with no terminal or product. No real-corpus rows, native finish execution or measured joint peak here. The remaining reader copies, fold allocations, other files and release order must be accounted for separately.
