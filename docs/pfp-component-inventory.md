# PFP → ordered rows: reviewed source inventory

Source snapshot: `9c26dccc`. This is an inventory, not a second design. [The target](../TAPE_VISION.md) is the authority. `N` = input bytes; `m` = phrase occurrences; `D` = dictionary symbols including encoding/overlap; `U` = owned offsets **summed over distinct phrases**. `U` is neither `N` nor the number of distinct representative strings.

| Phase | Implemented and evidenced | Reuse boundary |
|---|---|---|
| Parse and lexical naming | [`parse::parse`](../xsa/pfp/src/parse.rs) writes `(start,len)` in text order. [`dictsort::dictsort`](../xsa/pfp/src/dictsort.rs) orders/deduplicates phrase references, then annotates the sequence as `pa.bin`. | Historical `pfp_sort_r` uses **nonoverlapping** spans: when a trigger at `p` fires, the next start is `p+8`, not `p`. It suppresses early triggers, can force a cut at 65,535 bytes, and has no XSEP input. Not an overlapping PFP dictionary by renaming the files. |
| Sort the parse and induce an upper level | [`main.rs`](../xsa/pfp/src/main.rs) sends lexical IDs to `sa_kernel_int_raw` or [`levels::build_level2`](../xsa/pfp/src/levels.rs) and `unit::run_level` at ID stride. [10 GB v8 receipt](../RESULTS_TAPE_READER.md#10-gb-recursive-rust-full-reference-identity): 305,930,242 → 18,873,798 → 305,930,242. | Two levels, not arbitrary recursion. Check `parse_ids` itself: it compares with preceding positions at distances `1..=w2`, not the byte parser's `k..k+w-1`. The integer fallback when dictionary prefixes are present walks the lower ID sequence. Whole-product identity does not prove uniform triggers or a bounded-memory kernel. |
| Dictionary group order and expansion | [`overlap::construct`](../xsa/pfp/src/overlap.rs) uses a **content-only** predicate on complete 8-grams, with overlap; calls `order(&pa, ...)` and separately `order(&dict, ...)`. The latter is a **dictionary** SA, not a corpus SA. Buckets of occurrences follow next-parse-suffix order; equal representatives merge by those ranks. Boundary and interior byte LCPs are distinct cases. [Fixture evidence](../OVERLAP_PFP_PROBE.md). | Working in-memory reference, not an implementation of the one-sided trigger or the workspace law. Its callback uses a byte placeholder at position zero, not the direct writer's predecessor code 256. |
| Already implemented beyond the fixture | [`overlap_resident::run`, `flush`](../xsa/pfp/src/bin/overlap_resident.rs), [`DictSort::sort`](../xsa/pfp/src/overlap_dict_index.rs), [`Sweep::tiles`, `scan`, `emit`](../xsa/pfp/src/overlap_radix.rs): order `P` and the dictionary, retain per-phrase occurrence lists, visit disjoint dictionary-rank ranges without cutting a tie, join ordered row blocks. [`overlap_radix_test.py`](../gates/overlap_radix_test.py) already varies cuts and checks seam LCP and predecessors. [Measured scope](../OVERLAP_DEFAULTS.md). | A useful emitter, not a bounded dictionary orderer: the encoded dictionary and its SA (`4D` or `8D` bytes for the SA alone) are resident. The research executable has rung-specific admission checks. Don't copy them into the product. |
| Direct v10 finish | [`build_stream::context`](../xsa/src/build_stream.rs) consumes positions and XSEP; [`finish_row_stream`](../xsa/runtime/bit6/stream_finish.hpp) consumes ordered row43 and the m20/m15 trailer. [Installed-command receipts](../gates/receipts/build-stream/). | This consumer is **not** `pfp_sort_r`'s `PieceCutter`/SXLS writer. It requires one structural END row, original positions, exact adjacent byte LCPs and 256 as predecessor for position zero. Receiving a doc-aware index from it does not show that upstream parsing respected document cuts. |

**The loops that disqualify two shortcuts.** [`unit::distribute_window`](../xsa/pfp/src/unit.rs) invokes [`scan_order::phrases`](../xsa/pfp/src/scan_order.rs) per window: one visit per distinct phrase, then each strided offset, then filter. At byte stride it is `U` visits per window, not `N` sort records; the optional physical-order iterator also traverses `P`. The installed `build-stream` does not call this Rust code. Its [driver](../xsa/runtime/tools/build_stream.py) calls `stream_rows`; its [epoch loop](../xsa/runtime/rolling/finite_epoch_emit64.hpp) calls [`Direct::encode<true>`](../xsa/runtime/rolling/finite_direct_route64.hpp) and revisits all owned offsets per posting batch. Neither loop becomes conforming because its output matches an oracle.

**First integration question.** At the parser → dictionary boundary, test whether actual trigger events support prefix-free representatives before feeding them into another implementation's expander. Check natural cuts separately from forced cuts and EOF. Don't silently switch triggers, insert per-doc ENDs, or change the suffix order: the existing v10 row producer orders one finite text; XSEP currently reaches `stream-context`, not `stream_rows`. The producer's treatment of real document seams needs separate evidence. Test the compatibility of the components before adding an emitter, a CLI or a scale run.
