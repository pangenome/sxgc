# A hard live-inode bound for the v8 run pieces

This is a handoff option, **not a product launcher**. The 100 MB [credit study](overlap_finish_credits.md) reserved 78 full PRC1 payloads (`6+64+8`). Six writer credits alone do not enforce this: the consumer acknowledges a band *after copying* but can defer deletion until the covering m1 blocks are durable. Counting a directory after the next batch of writes is too late; counting only its top level is wrong. The goal here is to enforce a refusal **before** creating another payload, without modifying the frozen finish or fabricating an acknowledgement.

* The sole sink assigns sequential piece `i` to slot `i % 78`. Lazily create each slot exactly once under a fresh private `frag.pieces/payload-slots`. The sink holds its FD and name. Before reuse, require the name to identify that regular inode, extent equal to its last image, and `nlink == 1`. If a previously published link survives, **fail**, don't spill, overwrite or wait indefinitely. An advance of `frag.runcols.consumed` does not affect this test.
* Compute `44 + 5*q + 16*ceil(width*q/64)` before writing. At width 27, `q ≤ 65,536`, at most 770,092 bytes. Truncate/rewind the retired slot; the shared PRC1 serializer sees a bounded `Write`, not a seekable FD. Short/extra writes cannot publish a new band. Fsync the image, then hard-link (no replacement) under `p-i-0`. The existing BPG1 marker is published afterwards as usual. The private name and the transport name cost **one** logical payload, not two. There is no data copy. Even reusing an equal-sized slot is a new image.
* All slot payloads, including inactive and partially written images, are charged throughout the sweep: **78 × 770,092 = 60,067,176 B**. This bounds the union of underlying regular-file payload extents even if an observer temporarily holds a copied FD to an older published name. It does **not** make a stale reader's contents immutable across reuse. Correctness requires the audited finish (`read_stream_band` closes before returning credit; `releasePieces` only unlinks after the container sync), a private namespace and no external readers holding payload FDs/mmaps across retirement. Use metadata, not an inspector that pins inodes for the entire run. The bound is not blocks allocated, total writes, or peak RAM.
* The sink verifies the expected run total, removes only its **private slot names**, and drops all its FDs **before** publishing BPT1 terminal. Remaining canonical PRC1 links stay readable even for the last short band; nobody outside the frozen finish removes them. This order matters: if all retired payloads stayed linked in a descheduled process through m5, assuming their 60 MB could be reused would be wrong. Terminal, m1 close, the forced `releasePieces(true)` and empty pending list must precede the m5 spools. Do not use this protocol for restart. Preserve partial files on failure.

`XSA_TEST_V8_100M_PIECE_POOL=1` opts in only to the external narrow **100,000,503-byte** sink with fixed 6/5 credits, batched SXLS, spacing 128 and two requested threads. The parent must provide a fresh canonical 0700 arm root; the sink creates `merged` and `bands` without removing an old directory or a stop marker. Existing paths and modes are unchanged when the option is absent. A future supervisor must authenticate raw, remap, binaries and source, start only the known non-spooling consumers and gate publication on all exits. The relay checks the incoming suffix stream; the pool itself does not authenticate rows. Bounds for other files, release/liveness and simultaneous RAM are independent obligations. [Fixture receipt](../gates/receipts/v8-piece-pool-fixtures/): five generated cutter streams match an independent bitwise wire oracle, including a full 65,536-run piece, short/exact terminal and cyclic slot reuse. A retained reader FD and multiple names still identify one charged extent; advancing a consumed marker without unlink refuses before truncation. Short, extra and out-of-sequence images, link/identity substitution, premature retirement, stale directories and STOP were refused. The normal handoff/row43 and batched-SXLS wire regressions also passed. No v8 product at the new settings, performance result, v10 or larger rung admission follows from these tests.
