# Can short, indivisible prefix ranges cover the large two-code cells?

The [prefix certificate](../gates/receipts/target-prefix-vocab/) leaves 115 positive two-code cells without a `D≤192,000,000` guarantee. Two definitely exceed it. The new question is whether a **static alternative** splitting by raw prefix through nine codes can certify a disjoint bounded partition. The archived m20 tree supplies shallow branch counts for this feasibility study, **not rows or payloads for an overlap build**. A later standalone producer would need its own reproducing/validating mechanism, exact range seams/counts, wave/storage budgets and timings. The existing sampled splitter hasn't changed.

**Boundary safety, in the right direction.** Global byte suffixes are not clipped at document ends; the frozen m20 tree *is*. Don't just treat every count in it as global. At depth one, no real byte can cross a boundary. The root must reproduce the raw first-byte histogram and one virtual END. For the framing byte `0x1e`, compare every child to the exact raw bigram scan. The increase of its END count over raw text END must equal the sum of its deficits at real children **and the number of internal document cuts** (`m15.docs−1`). Thus **every internal boundary follows `0x1e`**. The converse is false: the file has literal internal separators. No scanning for separators to infer starts. A string containing no `0x1e` cannot cross any such cut, or end just before a new document. Its branch histogram (including any true text END) is therefore exactly the global raw histogram. Any particular nonempty prefix that contains `0x1e` can have at most its global byte frequency in occurrences (fix one offset in that prefix), which must be below the slot cap. So no heavy prefix we expand contains this byte. An absent/pruned branch is not blithely counted as absent from raw: we only expand a supported node under this law and require the exact child masses to sum to its raw mass.

**Why stop at nine?** An ordinary word owns all but its eight-byte overlap. Even its final owned byte heads a finite suffix of at least **nine** bytes. Every occurrence represented by a given `(word,offset)` descriptor therefore takes the same path through any cut of length ≤9; a shorter terminal tail comes only from the unique EOF word, with structural END. These cuts preserve complete-key ties. For a parent with exact `R` rows and `L≤D≤H` descriptors and a positive child with `c` rows, use `max(1,L−(R−c)) ≤ D_child ≤ min(c,H)`. Do not multiply a local distinct/occurrence ratio by child rows. A ninth-byte residual with `upper>slots` but `lower≤slots` is **uncertified**, not a proved overrun. If the eight bytes at offsets 1..8 of that prefix trigger, the next cut is exactly one byte ahead and this prefix already identifies one whole finite tail. Otherwise no ordinary descriptor in this bin ends at length 9: a measured tenth-code refinement would be tie-safe (unique EOF may end). m20 has **no tenth-code counts**. Beyond this horizon do not partition by arbitrary raw continuation as if it were still a finite word.

**Measurement.** First replay the actual two-code bounds offline. Read a fixed header/directory, m15 count and the 2,333,923,624-byte m20 to check CRC against the pinned directory and record its SHA; no full index hash, no new text read or cache eviction. Pass a read-only FD to a qualified frozen reader which maps only the pages covering m20 and consults the 115 parents and required descendants. Its existing transient first-edge `u32` array is **86,828,156 B** for 21,707,038 nodes, not a suffix array. Retain a bounded branch dump, not per-row data. Independently reconstruct disjoint lexicographic leaves, all positive rows and rank spans (rank 0 separate), hash leaf extents, report any residuals with actual lower/upper/row counts. Greedily pack only consecutive certified leaves; never bridge an unresolved hole. A complete range count is null if any leaf hasn't passed. No actual postings, D per range, epoch count, bandwidth or wall promotion. One pinned CPU / 256 MiB including cache / no swap, ≤150 s, parent attributed input ≤m20+96 MiB, observer ≤1 GiB, controls/observations sampled ≤20 MiB, 8 MiB native output cap, bounded STOP/deadline. No raw/index copy and no generated column.

**[Real archive check](../gates/receipts/target-m20-cuts/):** 113/115 inspected parents now have complete partitions bounded by the slot count. Two residuals—nine spaces (1,169,281,595 raw rows) and nine hyphens (257,804,274)—are not proved oversized or fit. Neither has a trigger at offset 1. All other leaves cover 98,572,914,131 real rows. No producer changed.
