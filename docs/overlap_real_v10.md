# Real 100,000,503-byte v10 pair

**Complete matched pair passed.** [Measurements, exact member tables, source and worker receipts](../gates/receipts/real-v10-product-100m/). Resident and rolling indexes match in all 87,192,432 bytes. Raw→joined 94.747 vs 146.871 s (rolling/resident **1.550×**), peak shared 1,751,048,192 vs 665,382,912 B. Sampled physical scratch plus reservations 185,036,800 vs 196,960,256 B, both below the enforced outer ceilings and 2N. No native-XFS timing or 100 GB permission implied.

**First attempt STOP; physical capacity treatment.** The native first reference stopped on a per-log sublimit, with no completed row proof or product. Its XFS front allocated **233,312,256 B** despite staying inside the *logical* bound; [preserved evidence](../gates/receipts/real-v10-first-stop/). The retry gives the sink 192 KiB out of the same aggregate log reservation. It puts **all data scratch** in a fresh preallocated fixed-capacity filesystem image on the same NVMe, mounted unprivileged via fuse2fs in the build cgroup. Raw inputs, durable partial/final index, and bounded controls remain separate. This is a matched **quota-filesystem** product comparison, not native-XFS performance. Both arms count filesystem service CPU and cache. No global eviction, root mount or scale grant. [Generated tests and rejected cases](../gates/receipts/real-v10-quota-fixture/).

Physical bound: reference 168 MiB and candidate 181 MiB preallocated **including all guest metadata and speculative allocation**, plus 4 MiB controls, 1 MiB pipes and 6/4 MiB resident queue/producer margin: **187,695,104 / 199,229,440 B** versus 200,001,006. Do not add the image to its guest file extents as if they were two disk copies. Measure the outer allocation AND the inner logical/allocated files, deduplicate hard links, count open unlinked files. Before each real front, require free guest blocks/inodes for the actual phase bound; reserve full rounded pool extents, even 590 block-rounded progress records, directory/temporary margins and m20. The candidate cap on m20 is the size established by the independent successful reference, not an assumed ratio. `-m 2` retains 2% emergency blocks; no alloc-all-blocks mode. The first `-m 0` generated setup correctly refused: [fuse2fs v1.47.0 `fs_can_allocate`](https://github.com/tytso/e2fsprogs/blob/v1.47.0/misc/fuse2fs.c) substitutes **10%** for a zero reservation. Outer preallocation does not entitle the job to all those blocks. Unmount and reap the first daemon, privately evict/verify the backing file, and remount before the prepared clock. FUSE2 lacks NOREPLACE for directory rename; `pos-manifest` uses only a no-replace hard link after both outputs are fsynced. Keep immutable failed images/STOPs, retire only a fresh closed image after full product and checks.

**Second STOP, before stream.** The extent-backed front fit the physical limit, but deleting the 127,708,112 B dictionary returned EIO; a later guest STOP write got EROFS. [Preserved failed arm and counters](../gates/receipts/real-v10-extent-stop/). No completed reference or candidate from that arm. Switch only the private filesystem layout to ext2 direct/indirect blocks, not the suffix algorithm or archive format. At most two base pointer blocks per large file plus one per 4 MiB of non-tiny payload; all files here are below the triple-indirection threshold. Charge that upper bound to usable formatted capacity, keep the same outer allocation and CPU/memory grants. Require offline read-only `e2fsck -fn` after each unmount (before cold backing handoff and final retirement), explicit free-block return after dense column deletion and normal host STOP/reap even if the guest cannot accept a marker. [Generated full-length column tests on the target NVMe](../gates/receipts/real-v10-block-fixture/).

**Objective:** replace suffix ordering, not the data structure. Each builder must go from a cold authenticated real Pile prefix to a complete boundary-aware v10 container, including chi and members 15/20, without m14. The verifier checks all 100,000,504 suffix positions, adjacent raw byte LCPs, BWT predecessors, EOF and the independent final rank before releasing the tail. Historical v8 rows are useful; a historical v8 container is not the reference product. [Input proof](../gates/receipts/real-v10-map100/), [fixed tool pins](../gates/receipts/real-v10-100m-tools/).

- Reference: independent older packed lexical partitioner + four-lane resident dictionary sorter. After the resident's emit barrier (no FD or mapping left on its private tape), retire the fresh tape and feed bounded, original 32,768-position bands to the **banked band trie**. No borrow from the rolling producer. Send the original narrow rows to the checker. Cross-check seven stable base payloads against the original 100 MB v8 builder as a further independent check. m7 must carry the *new* complete canonical remap.
- Candidate: `front64 pos-manifest` → fresh `parse64 rank` + certified inverse SHA → staged four-worker rolling posting images (50,000,251 B cap, 192,001 slots) → directly streamed Rust trie, no position file → checker. The two paths pay the same proof and have the same narrow handoff to the two-thread sink and immutable v10 finish. `--container-stream --with-chi --no-lcp-runs`, PFCK=64. Both append the in-build m20 and embed exact XSEP m15 using the original v10 code, in place. The new CLI checks exact lengths/head/profile in a private working directory; the tiny generated fixture shims are unchanged.

**Fit before launch.** [Executable ledger](../gates/overlap_real_v10_plan.py). Same guarded inode pools as the tested v8 wire, **not** a v8 finish: 78 × 770,092 B PRC1 and 5 × 2,410,736 B SXLS. Both pools retire before terminal, last pieces after durable m1 absorption and before m5. The verifier fences runs, max LCP, slice extents and folded load geometry on the exact stream. Prefer refusal to predicting progress from a `.consumed` marker.

**RAM / time / failure policy.** Same four pinned build CPUs and 2 GiB shared (including supervisor, libraries, heap/stack, mapped raw and cache), no swap, per arm. Candidate modeled producer arrays capped at 320 MiB; resident modeled arrays capped at 1.4 GiB (older measured RSS ~1.21 GB on these rows). The finish and tap have separate 192/160 MiB `RLIMIT_DATA`, sink 64 MiB, process stacks 8 MiB (not the known broken 1 MiB profile); these are additional anonymous-allocation guards, not RSS limits. For scale: checker 98,304-byte packet plus private 100 MB mapping; sink packet + codec <0.7 MB, two run buffers and encoding temps; two finish slots and per-job LCP payloads, PFCK, bitmap, directory buffers, raw mapping and output cache also coexist. The closed-form fold bound is not whole-finish RAM. Reclaimable pages, process RSS and cgroup peak are distinct and not added as disjoint amounts. Fifth pinned CPU/140 MiB/zero-swap independent checker in a separate user service. Private fsync/fadvise/mincore; strict per-worker exits, deadline/STOP/IO caps, never global cache eviction. Cold raw plus checker + XSEP/remap **200,069,606 B per arm** declared separately. One partial/final index per arm (128 MiB cap), not scratch. Reference residual non-input/non-output data must be <1 MiB before the candidate and still count. Walk nested files, dedupe hard links, include private unlinked open FDs; refuse unsupported deleted mappings. Disk allocation is reported separately from logical scratch. One bounded 901–1500 s pair lease. No larger dispatch.

Clock raw→joined, prepared→joined, full proof/queries and publication, and service separately. Prepared branches start with *different* columns (packed IDs/tape vs certified inverse); raw comparison is primary. Both include concurrent witness and raw row proof on the critical path. Time input setup, CRC/full-byte identity and doc/context/cross-cut queries separately from construction. Record Linux `wait4` task-attributed block counts, worker CPU and max RSS, optional cgroup `io.stat` (unknown if absent), memory stats at sample and hard cgroup peak. Position/row wire bytes are not physical IO. A generated binary test, a successful isolated row pass, or a merely similar index does not pass this comparison.
