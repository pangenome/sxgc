# Splitting the two long homogeneous prefixes without reading another target byte

The [depth-nine audit](../gates/receipts/target-m20-cuts/) left two holes: `20` repeated nine times and `2d` repeated nine times. **A row count above 192M is not a distinct-count overrun.** Can we bound a *complete alternative* partition without estimating the number of distinct words or running a tenth-byte (and then eleventh-byte…) scan? The answer should depend on the observed structure of these holes, not on an assumption that all long prefixes are rare.

**Finite equality first.** An ordinary word ends in its eight-byte trigger; its last owned byte starts a finite tail of length nine. For either residual byte `x`, `x^8` **does not trigger**. Hence any ordinary tail beginning with `x^9` contains its first different byte *inside that finite tail*. For EOF, the whole raw tail is available and exhaustion sorts below any byte, even NUL. Classify by the initial run length `j≥9` and the side of the first non-`x` code (`below x`, including END, or `above x`). This pair is the same on every raw occurrence of an exact finite key. It is **not** legitimate for arbitrary bytes: `2c^8` triggers, so an ordinary finite `2c^9` may correspond to many distinct raw run lengths. Refuse that case. Embedded `0x1e` is ordinary text here; neither residual contains the framing byte. The previous certificate, not a delimiter search, proved the histograms exact.

**Count by maximal raw runs.** Let `R9` be the row count of `x^9`, and `E_s` the sum of real depth-eight branch counts on side `s`, including true text END on the lower side. Each maximal run of length `L≥8` with that exit provides one depth-eight exit; it contributes `max(0,L−8)` rows to `R9`. For any fixed `j≥a≥9`, there is at most one position of exact initial length `j` per such run, and each supporting run contributed at least `a−8` rows. Therefore the number of **rows**, not just descriptors, at `(j,s)` is at most

```
p = min(E_s, floor(R9 / (a − 8)))
```

Group consecutive lengths `[a,a+w)` on the same side where `w≤floor(slots/p)`, clipped at `1+min(max_phrase,R9+8)`. This is safe because even summing the individual upper bounds gives `w*p≤slots`. No assumption of a geometric run-length distribution or a sampled duplicate rate. A maximal run also cannot exceed the largest parsed word: if it has length ≥9 its suffix at the start is classifiable by an owning finite word as above. Omit zero-mass sides; refuse if even a singleton length is not certifiable. On the lower side lengths sort **increasing**, all lower-side keys precede the upper side, and upper-side lengths sort **decreasing**. All these groups are consecutive lexical intervals. The approach deliberately sacrifices tightness for a small reproducible proof.

**What a complete cover means.** Replay the entire preceding shallow proof and its exact certified rank extents on repository receipts. Replace only its two residual leaves with these groups. Pack the other consecutive shallow leaves at the same slot bound, never across a hole. The emitted JSONL is a *feasibility table*, not byte SA rows or a producer input: `prefix, first_key, last_key, first_rank, past_rank, D_lower, D_upper` or `shell, byte, side, first_length, past_length, upper`. Keys list ordered codes (`END=0`). Individual shell rank boundaries are **unknown**, some nominal bands can be empty. Raw mass is known for the parent as a whole. In particular the **sum of shell uppers is not the number of rows, descriptors, allocated slots or bytes written**. Keep global END at rank zero separately. Bound an indivisible finite key by the largest *unpacked* shallow leaf or a single-length/side shell, not by the largest merged band.

For at most `b` nonempty resulting bands, reuse the checked rolling EF upper on the actual layout (`m` from the scan, `k_lower,U_upper` from the 10 GB certificate, four stripes). With virtual universe `v=32*(m+floor((U_upper−k_lower)/32))`, bound total by `upper(U_upper,v,b)` and one complete wave by `W=upper(slots,v,min(b,4))`. With a 50 GB posting slot, if `W<cap`, every nonlast greedy epoch holds **strictly more than `cap−W`**; the count is at most `ceil(total/(cap−W))`. Exact census/empty-band removal before opening are still required. This can remove the *mathematical* every-range-fit condition for this particular alternative, not for the existing learned splitter. It neither certifies 4-way occupancy nor implements an efficient stand-alone router. No target arrays, disk allocation, verifier/service time or build grant follow.

**Falsification.** Enumerate bags of maximal runs with small, one-sided, long and absent cells. Independently materialise raw suffixes, the actual w8 words, repeated records, descriptors, finite ties and EOF on generated binary texts including NUL and 255; check every position's classification, both orders and each upper. Show a real trigger counterexample for the wrong generalization. The first local test draft failed its own tie-coverage assertion: repeating a word duplicated descriptors but did not make *different* descriptors with equal finite tails. The corrected generated test puts different bytes before the same run and an actual common `x^7y` ending trigger after it; it asserts distinct descriptors really do tie. No target run was involved. One separate guarded, 1 CPU / 192 MiB / no swap replay using only small receipts and generated data; no full text or archive open.
